## Recent changes — money-manager pass (this session)

1. **Training is execution-faithful (`Application/Services/MoneyManagerTrainingService.cs`).** `SimulateBarrier` now replays the desk's own plan, not a stop/target toy: `NormalizeTradePlanWithinStaticLimits` for `DAY` (and `NormalizeTradePlan` elsewhere), the tick-grid barriers, the effective round-trip fee from `ComputeEffectiveRoundTripFeeRate`, the `+1R` break-even ratchet and the `+1.5R` causal EMA20 trail (`RatchetTrainingStop`, `BuildEma20Series`, `CausalIndexRegime`). `NetRealizedR(entry, exit, buyRate, sellRate, netRisk)` charges the two legs separately. `TrainingTrial` / `TrainingOutcome` / `FitChoice` carry the new fields.
2. **The model learns the *residual* over the prior.** `eta_i = logit(prior_i) + β₀ + w·z_i`: the structural probability enters `LogisticModelTrainer.Fit` as a per-trial **offset**, so the heuristic and the learned weights can no longer double-count the same signal. Sample weights are `1/√(signals on that date)` × `clamp(0.5 + 0.5·|RealizedR|, 0.5, 2.0)`, normalised to mean 1 so the L2 strength stays comparable across fits.
3. **Sizing is fractional Kelly, not a made-up percentage.** `OptimalKelly(validation, probabilities)` computes `f*_i = max(0, p_i − (1−p_i)/b_i)`, funds only trades with `EV > 0`, and returns `clamp(c·f*_i, 0, 0.025)`; the persisted number is a **Kelly fraction multiplier** (`0.25` = neutral), which the edge service applies to its own stake. The promotion gate is now `validation ≥ MinimumValidationTrials`, `train+validation ≥ MinimumTrials`, `trainedBrier < baselineBrier`, `LogLoss ≤ baselineLogLoss` and `policyExpectancyR > 0` (`ComputePolicyExpectancyR`).
4. **One ticket per ticker, sized against the real book (`Services/BookSizingSnapshot.cs`, new).** `PortfolioService.GetBookSizingSnapshotAsync` reads account + open trades + the session's metrics **once**; `snapshot.For(ticker)` rebuilds exactly the `OrderTicketContext` the single-ticker endpoint builds — that ticker's sector room, its own `AtrPct` (the slippage estimate) and, when the name is already open, its pyramid state and unrealized R. `SignalRunMapper.ToDto(..., BookSizingSnapshot? book)` plus `SignalPipelineService` / `SignalsController` pass it through, so a run no longer sizes every pick as the first position of an empty book. `GetOrderTicketAsync` gained an optional `EdgeAssessment? edge` (the old `EdgeAssessmentWriter` argument is gone) so the Kelly stake and the pesos come from one assessment.
5. **Research is priced by the same dials as the daily run (`Services/TickerResearchService.cs`).** Optional `SignalOutcomeService`; `ResolveRegime` reads the PSEi bars it just fetched (falling back to the stored snapshot only when the index is unavailable); `TryLoadLearnedModelAsync` / `TryLoadCalibrationOffsetPctAsync` load the published model and the live calibration offset; `SetupEdgeRequest` now carries regime, breadth, fee rate, calibration, features and the learned model; the ticket is sized off that same assessment with `ResearchSizingNotionalPhp = 50_000`.

6. **The replay is a book, not a serial bet (`Application/Services/BacktestService.cs`).** Constants `MaxOpenPositions 5`, `MaxPortfolioHeatPct 6`, `MaxPositionsPerSector 2`, `MaxSectorExposurePct 35`, `WalkForwardRefitSessions 60`, `MinimumWalkForwardTrials 40`, `SmallSizeRiskMultiplier 0.50`, `KellyReferenceFraction 0.02`. `BuildCandidate(metric, profile, sector, regime)` prices the tick-rounded plan, rejects anything under **1.2R after fees** (`ComputeNetRiskReward(..., feeRate)`), records the structural `PriorProbability` (`ConvictionScore: 50`, no breadth, no sector quadrant — a replay must not price a reading it did not have) and `TrainedModelFeatures.FromMetric(metric)`. `LabelOutcome` grades each candidate with the full exit ladder, so the walk-forward refit learns from the money the replay would have made.
7. **`WalkForwardEdge` — the replay's own model (new, nested).** Refits every 60 sessions on the candidates whose `OutcomeDate` had already passed: residual-over-`logit(prior)` through `LogisticModelTrainer.Fit`, cluster weights `1/√(signals on that date)`, **fixed** λ = 25 (a replay has no held-out slice to scan λ on). It is only used once it beats the neutral base rate on its own resolved trades; otherwise `Probability` returns the prior untouched. `KellyMultiplier(p, b)` = `clamp(quarterKelly / 0.02, 0.50, 1.50)`. The acceptance test is in-sample, so it can sharpen sizing **inside** a replay but never promotes itself to live pricing — that stays the offline trainer's decision (stated in the class comment).
8. **Funding rules in `Simulate`.** Exits fill on the stop (checked before the target), the target or the time stop; `RatchetStop` manages the rest. Before sizing, the book is marked to market; then each candidate, best score first, must clear the position cap, the same-ticker rule, the per-sector **name** cap, the per-sector **notional** ceiling, the `EV > 0` gate (with `NetRiskReward` already net of fees) and the remaining heat room. Size is `equity × RiskPerTradePct% × drawdown × verdict × Kelly`, so a fully invested book still sizes the next setup the way the live ticket would; the **cash balance is only a funding check** — a clip the free cash cannot settle is trimmed to whole board lots (fees *and* entry slippage included) or dropped, never overdrawn. Entry slippage leaves cash (`slippagePhp`), sits on the position and the trade, and is subtracted from `NetPnlPhp`, so the curve and the per-trade R agree.
9. **Cold boot refits in the background (`Infrastructure/Scheduling/DailySignalSchedulerService.cs`).** `ExecuteAsync` queues `BootstrapRetrainAsync` through `Task.Run` before the delay loop, so the close run is still armed immediately. `NeedsBootstrap(models)` is true only while a horizon is `UNTRAINED` (a `PRIOR_FALLBACK` is a decision, not a cold start); a failed fetch (404/429/offline) is logged as a warning and the structural prior stays in force until the weekly slot.
10. **Tests (+6, now 369).** `BacktestServiceTests` gained `BuildPortfolio` / `BuildStock` / `CreatePortfolioService` / `MaxConcurrent` and three cases: an eight-name board holds **exactly** `MaxOpenPositions` clips at once, a six-name Banks board holds **exactly** `MaxPositionsPerSector` and never breaches the sector notional ceiling, and simultaneous outlay (fees + slippage) never exceeds the starting capital with every equity point positive. `TickerResearchServiceTests` gained `ResearchAsync_prices_the_causal_regime_instead_of_the_stored_label` (a bearish index prices below a bullish stored label, and the stored label cannot leak back in). `DailySignalSchedulerRetrainTests` gained both `NeedsBootstrap` cases. The older causality tests (append a future crash bar / turn the index bearish later → past trades byte-identical) still pass, which is what keeps the refit honest.

## Active decisions

- **The account is the unit of risk, not the idea.** Sizing is always a fraction of *equity*, never of the cash balance; cash only decides whether the computed clip can be settled, and an unaffordable clip is trimmed to whole board lots or dropped — never silently shrunk by some other rule and never overdrawn.
- **A replay must fund what the live desk would fund.** The same heat cap, sector name/notional caps, `EV > 0` gate, drawdown governor, Kelly dial, board lots and per-leg fees decide a simulated entry as decide an order ticket. If a rule is not in the replay it does not exist.
- **The learned model is a residual, never a replacement.** Both the offline trainer and `WalkForwardEdge` fit `logit(prior) + β₀ + w·z`, so the structural dials keep their meaning and the weights explain what the dials missed. A refit that does not beat the neutral base rate is discarded (`PRIOR_FALLBACK`) instead of being used because it exists.
- **A walk-forward refit may only see closed windows.** `Refit` is fed candidates whose `OutcomeDate` is strictly before the session being priced, which is what keeps the append-a-future-bar test byte-identical.
- **In-sample acceptance is enough for a replay, not for live pricing.** `WalkForwardEdge`'s only held-out check is impossible inside one window sequence, so its promotion test is in-sample and it can never write `TrainedHorizonModels`; only `MoneyManagerTrainingService` promotes.
- **One assessment per ticket.** The probability, the Kelly stake and the pesos on a ticket all come from the same `EdgeAssessment` (`GetOrderTicketAsync(..., edge)`), and the pipeline sizes each pick from `BookSizingSnapshot.For(ticker)` rather than a run-wide, ticker-less context.
- **The direction call and the wave plan are server-owned.** `MarketDirectionService` owns the five pillar weights, the 10–90 clamp and the three call thresholds; `WaveTradePlanCalculator` owns every tick-valid price, the chase ceiling, the entry status and the hold ladder. `plainAdvice.ts` may rename the call (Green / Amber / Red light), translate an entry status and format the prices — it must never derive a score, a trigger or a "you should sell" verdict of its own.
- **Top three first, the rest one tap away.** Simple mode renders at most three `AdviceCard`s and hides the remainder behind `Show N more`; the honest empty state ("Nothing is worth buying today") is a first-class answer, not an error.
- **A position check is a different read.** `queryKeys.researchItem(horizon, query, holding)` appends the reader's own cost/share, so the "already holding it" tab can never be served the plain buy plan from cache; switching back to the buy tab drops the holding and re-prices the plain plan.
- **Progressive disclosure over two codebases.** One payload, two presentations. New UI work keeps Simple as the default and puts dense/institutional detail behind `TechnicalDisclosure` / `OptionalDisclosure` rather than building a second data path.
- **Simple mode is copy, never maths.** `lib/plainAdvice.ts` may rename enums, translate ticket warnings and format the server `OrderTicket`; it must never recompute a probability, size, verdict, R multiple or P&L.
- **Mode is presentation state only.** `viewMode` never travels to the API; a stored run renders identically in both modes.
- **Theme is CSS, not props.** Light/dark lives entirely in custom properties under `:root[data-theme='light']` / `:root[data-theme='dark']`; components read tokens only, `index.html` pre-paints the stored choice, and no payload, component API or test depends on the theme.
- **One cache, verbatim payloads.** `lib/queryCache.ts` is the only read cache and stores exactly what the API returned; it decides *when* to refetch (`queryStaleTime`), never what a number is. Mutations seed it (`setQueryData`) or mark it stale (`invalidateQueries`), the shell shares one `portfolio:summary` with `PortfolioDialog`, and live-feed endpoints (`run-now`, `backtest`, `research/{query}`) are never warmed by a hover.
- **Abort is ref-counted.** A caller detaching (StrictMode remount, dialog close, horizon switch) releases only its own subscription; the upstream `fetch` is cancelled when the **last** caller leaves. That is what keeps hover-prefetch → click on one request instead of a `499` and a duplicate call.
- **Responsive is additive, never a second tree.** Mobile changes are media queries, card fallbacks and sheet positioning inside the existing components; no payload, view-mode branch or server rule changes per breakpoint. No new npm dependency was added for it, and touch targets/inputs follow the platform rules (≥36px, 16px inputs, `touch-action: manipulation`).
- **Company names are metadata, never a guess.** The API resolves only an exact ticker or an unambiguous company name and republishes the static `PseTickerCatalog`; `lib/pseNicknames.ts` may rank and label that list (and add familiar nicknames) but may never invent a ticker or widen a search into an ambiguous match.
- **Presets are payload builders, not risk maths.** `SAFETY_PRESETS` / `BUDGET_PRESETS_PHP` assemble a `PortfolioSettingsUpdate` and the welcome banner posts it; the server still clamps, validates and stores every value, and `safetyPresetForSettings` only highlights which card the stored numbers happen to match.
- **Plain copy and the cache are tested, not assumed.** `npm test` runs `node:test` over two files: `plainAdvice.test.ts` (29 cases covering `plainAdvice.ts` **and** `pseNicknames.ts`, so a threshold change that leaves a sentence lying fails the suite) and `queryCache.test.ts` (8 cases pinning the dedupe/abort/invalidation/research-holding-key contract). The browser build excludes `__tests__` and stays dependency-free.
- **Live-or-fail, no fallback.** Never reintroduce a synthetic/offline path. A dead feed is a `503` carrying the upstream reason; research and backtest inherit the rule.
- **Grounding is best-effort, invariants are not.** Retrieval, embeddings and the fast-extraction pass may fail silently (logged), but tick rounding, the static band, net R:R, board-lot sizing, citations, drift, drops, odds, verdicts, cash posture, the pre-mortem fallback, order-ticket sizing, the governor multipliers, sector caps, slippage/execution guidance and the blotter's cash/heat rules are always enforced by the server.
- **Odds and tickets are server-owned and single-sourced.** The model never emits a probability, size, verdict, ticket, sector quadrant or slippage figure; `ProbabilisticEdgeService` and `OrderTicketCalculator` compute them and the UI only formats them.
- **A learned model must earn its promotion.** `LearnedEdgeModel.FromActive` returns `null` unless the row is `IsActive`, so a rejected fit can never reach live pricing. The gate is: ≥25 held-out trades and a held-out Brier below the neutral prior's on the same purged slice.
- **Learned odds are bounded.** The tilt is half the model's deviation from its own base rate, capped at ±6pp, applied after every structural tilt; a model may inform the prior, never dominate it. The Kelly multiplier stays in `[0.15, 0.35]` of full Kelly and only rescales the existing Quarter-Kelly stake.
- **A rejected fit is stored, not hidden.** `PRIOR_FALLBACK` rows are persisted with their scores and factors so the terminal, the API and the prompt can say why the prior is still in charge.
- **Training never blocks a run.** Weights are refit weekly in a separate DI scope after the first trading session; a fetch/fit failure is logged and the stored weights stay in force. An empty feed is a `503` on the training endpoints, never a synthetic fit.
- **Splits are chronological, purged and embargoed.** 70/30 by entry date, training trades whose forward window had not cleared are dropped, and `max(1, ForwardWindowBars)` sessions separate the slices, so the held-out score cannot leak.
- **A weak edge is scaled, never deleted.** `GovernorMultiplier` floors at 0.50, so a thin setup still gets a clip; only `WATCH_ONLY`, `HALTED` and a breached sector cap produce zero shares.
- **Volatility targeting only cuts.** `min(1, TargetAnnualVolPct / realized)` means a calm tape never raises risk above the book's own budget.
- **Drawdown is persisted state.** `PeakEquityPhp` lives on the account and is raised (never silently reset), so a restart cannot forget that the pod is in a drawdown.
- **Rotation is recomputed per run, persisted once.** `SectorRotationService.Compute` is a pure function of the session's metrics; a run only fills `SectorRotationJson` when the stored session has none, so replaying an old session stays consistent with its own metrics.
- **The ticket beats the local budget.** `lib/riskSizing.ts` renders `item.orderTicket` verbatim and keeps the ₱100,000 model-budget derivation only for ticket-less legacy runs, so the terminal can never contradict the server.
- **Dividends need a past ex-date.** Only payouts whose ex-date is on or before the trade date count toward the trailing-365-day yield; duplicates collapse to the largest payout.
- **The replay must stay causal.** `BacktestService` evaluates each session on the prefix that preceded it (including the index prefix for the regime gate and the EMA20 series), disables the empirical base rate, resolves same-bar stop+target ties to the stop, and refits its own nested `WalkForwardEdge` only on candidates whose `OutcomeDate` had already closed.
- **The replay is an account, not an idea.** Up to `MaxOpenPositions = 5` concurrent clips, `MaxPositionsPerSector = 2` / `MaxSectorExposurePct = 35` per sector, `MaxPortfolioHeatPct = 6` of open risk, fractional-Kelly sizing off the **marked equity**, and `EV > 0` after fees as the funding gate. Cash is a funding check only: a clip the book cannot settle (fees and slippage included) is trimmed to whole lots or dropped, never overdrawn.
- **The benchmark is charged less than the desk.** Alpha is `NetReturnAfterSlippagePct − BenchmarkReturnPct`, where the desk pays fees *and* slippage and the index pays neither. Any positive alpha is therefore conservative, and both curves share one chart scale so the gap is visible rather than massaged by a second axis.
- **A ratio is `null`, never `0`, when it cannot be computed.** Sharpe needs ≥20 sessions, Calmar needs a drawdown, CAGR needs two distinct dates — the frontend prints "not enough history", never a fake zero.
- **Pyramiding is one legal shape, enforced on the server.** Add only above the existing entry, only with the stop already at break-even, only at ≥+1R from the latest stored mark, never above the target, at most two adds; risk 0.50x then 0.25x. The add merges into the existing row on its fee-paid cost and `PyramidCount++`, so the blotter never carries two opinions on one name.
- **A trim is a settlement, not an edit.** Both legs must be whole board lots, `BuyCostPhp` and `InitialNetRiskPhp` split proportionally, the slice becomes its own `CLOSED` trade carrying its own `RealizedNetR`, cash is credited and the remainder's stop ratchets to break-even. The blended R of the two slices must equal the position's original total R. The bank-half quantity is therefore derived from **both** legs at the marked price (`ComputeRecommendedTrimShares`), never from the entry lot alone — an offered button must always be a request the server accepts.
- **Paper only.** The blotter never routes an order: the entry is priced at the planned level, the close at a supplied fill, marks come from the latest stored session, and every rule breach is a `400`, never a silent resize.
- **Probability is an estimate with a stated prior.** 0.42 prior, 12 pseudo-observations, `null` empirical rate under 60 bars, 50/50 blend with barrier geometry, bounded tilts, clamp `[0.05, 0.95]`.
- **WATCH_ONLY is a real no-bet.** Those names stay in the Top 10 for research context, carry zero risk-sized shares and cannot be taken as a ticket.
- **Caller cancellation is not a feed failure.** Rethrow it (guarded by `when (cancellationToken.IsCancellationRequested)`); only the provider's own linked timeout becomes a 503.
- **Unreported means `null`.** Do not substitute `0` for foreign flow, breadth, RS63d, VCP, the hit rates, beta, max drawdown, the FX dials, the cross-asset dials or a missing dividend.
- **Foreign flow has a provenance, not a guess.** `ForeignFlowSource` records `pse-dqr-live` / `pse-dqr-upload`; the prompt and the regime tile print it, and a report only writes the tickers and market total it actually states.
- **Secondary sources are best-effort, the tape is not.** Macro symbols, the DQR and the extra PSE Edge pages swallow failures (logged → `null`); the PSEi, USD/PHP and the announcement page keep the fail-fast `503` contract.
- **An upload owns one column.** `DailyQuotationImportService` re-saves through `MarketDataMapper.ToBatch(snapshot)`, so breadth, macro dials, rotation and FX survive.
- **A suspended ticker is a halt, not a flow.** It counts toward `UpdatedMetricCount` but not `MatchedTickerCount` and earns the deterministic `TRADING_HALT_RISK` hard trap.
- **Horizons are data, not branches.** New per-horizon behaviour belongs in `HorizonProfile` (backend) and `horizonMeta` (frontend) — now including the Simple-mode `friendlyTitle` / `friendlySummary` / `friendlyTab` / `holding` copy.
- **No new dependencies** unless clearly justified; tests stay offline by stubbing `HttpMessageHandler` / `IHostEnvironment`, never by skipping assertions. Test fakes are plain classes (no Moq).
- **SQLite stays** for the MVP; the repository boundary is the seam for a server database later.

## Open questions

- Does the multi-slot book actually improve the replay, or does holding five correlated PSE names at 6% heat simply amplify a market-wide drawdown? The first live backtest answers it.
- Is the `EV > 0` funding gate too strict for a thin tape? On the stub board it still funds 5 clips, but a real WEEK list may be filtered down to one or two names.
- Does `WalkForwardEdge` earn its keep? Its in-sample acceptance can only be justified by a replay that beats the same replay with the refit pinned to the prior — not yet measured.
- Is a fixed λ = 25 right for the replay's refits, or should it scale with the number of resolved trades (fewer samples → stronger shrinkage)?
- Are `MaxPortfolioHeatPct 6` / `MaxSectorExposurePct 35` / `MaxPositionsPerSector 2` the right pod-shop constraints for a PHP 100k practice account, where one 20% clip is already a fifth of the book?
- Is `KellyReferenceFraction 0.02` (a 2% quarter-Kelly stake = a normal clip) the right dial, and should the `[0.50, 1.50]` band tighten while `ValidationSampleCount` is small?
- The same ladder now lives in three places (`MoneyManagerTrainingService.SimulateBarrier`, `BacktestService.LabelOutcome`/`Simulate`, `WaveTradePlanCalculator`); is a shared exit-ladder helper worth the coupling before the triggers are frozen?
- Does the learned model actually beat the neutral prior on a real PSE tape, or does the 70/30 split with a 25-trade floor keep every book on `PRIOR_FALLBACK`? The first live refit answers this.
- Is ±6pp the right cap for the learned tilt, and should the cap shrink further while `ValidationSampleCount` is small?
- Should the weekly refit use the previous week's resolved outcomes only (incremental) instead of refetching 1080 days?
- Does the plain-English prompt actually raise thesis quality, or does it cost specificity the Pro reader wanted? The next live run should compare a rewritten thesis against the old style before the wording is frozen.
- Does the desk actually beat the PSEi now that both are drawn on one chart, or does the regime gate only cut the worst quarters? One real multi-year replay answers it.
- Are the ladder triggers (+1R break-even, +1.5R EMA20 trail) right for PSE volatility, or do they cut winners that would have reached the target?
- Is "trim half" the right default `RecommendedTrimShares`, or should it scale with how far past +1R the position sits? And should a losing position offer a trim at all, or only a cut?
- Should a pyramid add reset the trail anchor, and should the second add tighten the stop further than break-even?
- Should `STOP_BREACHED` / `TARGET_REACHED` auto-settle the position, or stay a manual confirmation as today?
- Are the verdict gates (`EV ≥ 0.15R`, `p ≥ breakEven + 0.05`, net R:R ≥ horizon minimum) calibrated for PSE fill quality, or too strict to emit `TRADE` on a thin tape?
- Are the governor bounds (`[0.50, 1.50]`, a 2% Kelly reference) right for PSE position sizes, or should the edge band be narrower?
- Are the sector cap (35% of equity, 2 names) and the `[soft 5%, hard 10%]` drawdown ladder the right pod-shop constraints for a book this concentrated?
- Is the slippage model (`2 × tick / price` + a √impact term capped at 1.5%) too punitive on mid-caps once real fills exist?
- Are the rotation weights (breadth 0.30 / stage 0.25 / RS 0.30 / volume 0.15) and quadrant bands (70/55/40) meaningful when many catalog “sectors” hold one or two names?
- Should research results be cached per (ticker, session, horizon) instead of re-fetching the chart on every request?
- Is the 10% foreign pillar weight (and the ±0.03 foreign tilt in the odds) right now that the flow is only reported for the sessions an operator uploads a DQR for?
- Should a DQR upload also rewrite the day's `BreadthAboveSma50Pct` inputs, or stay strictly a foreign-flow overlay?
- Should re-running a past date invalidate later runs' drift chain? (Currently each run only looks strictly backward.)
