# System Patterns — PSE Signal Desk

## Architecture

Clean Architecture with dependencies pointing inward:

```
WebApi  ──►  Infrastructure  ──►  Application  ──►  Domain
   └──────────────────────────────────────────────►  Application
```

- **Domain** has no package references: entities, enums and `PseBoardLotService` (pure PSE 15-tier board-lot/tick/static-band rules plus the fee-adjusted break-even, expected-value, Quarter-Kelly and risk-budget sizing math).
- **Application** references Domain + `Microsoft.Extensions.Logging.Abstractions`. Contains use-case orchestration, DTOs, pure services (`QuantitativeFilterService`, `ProbabilisticEdgeService`, `SignalOutcomeService`, `SectorRotationService`, `PseDisclosureClassifier`, `OrderTicketCalculator`, `HorizonProfile`, `MarketDataMapper`, `SignalRunMapper`), the stateful use cases (`PortfolioService`, `TickerResearchService`, `BacktestService`, `DailyQuotationImportService`) and the interfaces the infrastructure implements.
- **Infrastructure** references Application. Contains EF Core SQLite, the live Yahoo/PSE Edge market-data provider plus its `MarketData/MarketDataCache` and the PSE Edge daily-history fallback (`MarketData/PseEdgeHistorySource`), the Daily Quotation Report parser (`MarketData/PseDailyQuotationParser`), the SQLite RAG store (`Knowledge/`), both Ollama clients and the scheduler.
- **WebApi** references Infrastructure + Application. Controllers, DI, configuration, migrations.
- **Tests** reference all four projects and use xUnit with in-memory fakes (no network); persistence-level tests run against an in-memory SQLite connection.
- **WebApi** owns cross-cutting HTTP concerns: `Controllers/SignalsController`, `Controllers/ResearchController`, `Controllers/PortfolioController`, `Controllers/KnowledgeController`, `Middleware/RequestCancellationMiddleware` for aborted requests (answered `499`), `Middleware/ComplianceGuardMiddleware` for the deployment-mode/loopback/operator-key guard, `Services/DeskWorkGate` for "one expensive job at a time" and `Services/DeskRateLimitPolicies` for the named hourly ceiling the costly actions opt into. Signals routes: `GET latest`, `by-date`, `dates`, `ticker/{symbol}/history`, `scorecard`, `backtest`, `model`, `train`, `train-all`, `desk-memory`, `POST run-now`, `POST quotation-report` (multipart DQR upload); research: `GET /api/research/catalog` (static ticker + company + sector metadata) and `GET /api/research/{query}` (ticker or unambiguous company name); portfolio: `GET /api/portfolio`, `PUT settings`, `GET order-ticket`, `POST trades`, `PATCH trades/{id}/stop`, `POST trades/{id}/close`; knowledge routes: `GET`, `reindex`, `upload`, `DELETE`; plus `/health`.

## Signal run flow (the heart of the system)

`SignalPipelineService.RunAsync(runDate, horizon)`:

1. **Load or fetch market data.** Read the stored `DailyMarketSnapshot` + `StockDailyMetric` rows for the date. If absent, call `IMarketDataProvider.FetchAsync` (live Yahoo Finance + PSE Edge, fail-fast for the tape; best-effort for the DQR and the macro dials), run `QuantitativeFilterService.EvaluateBatch`, persist both, build the snapshot in memory.
2. **Guard rails.** Throw `MarketDataUnavailableException` when the provider returns no stocks, when no ticker has enough candles for the horizon (`HorizonProfile.MinHistoryBars`), or when nobody clears the liquidity floor.
3. **Select candidates.** `HorizonProfile`-aware `SelectCandidates` applies the PHP 5M floor, sorts by `QuantPreScore`, then turnover, then ticker, and caps at 25.
4. **Retrieve grounding.** `RetrievePlaybooksAsync` builds a `KnowledgeQuery` from the horizon mission, the top-8 `TICKER (SECTOR)` list, the dominant sector and the union of `PseDisclosureClassifier.DetectTrapFlags` over the candidates, then calls `IKnowledgeRetrievalService.RetrieveAsync`. Retrieval failure logs and returns an empty list — the run continues **ungrounded** instead of failing a live signal.
5. **Build the request.** Include regime context, **universe breadth** (`MarketBreadth`: % above 50D/200D, Stage-2 count), **sector rotation** (ranked `SectorRotationDto` cards), the **walk-forward calibration offset**, the **promoted learned model + each candidate's 12-factor vector**, the **desk memory**, candidates (indicators, board lot, static band, Weinstein stage, RS63d, ATR%, VCP ratio, per-horizon hit rates, accumulation/quality factors, sector quadrant, tick spread, trap flags, disclosures and `decimal?` foreign flow), the retrieved playbook snippets (reference + title + excerpt) and **yesterday's Top 10** for hysteresis. The model/calibration/memory loaders are resilient: any failure logs and falls back to the prior, a zero offset or empty memory.
6. **Generate.** `IOllamaSignalEngine` → `OllamaSignalEngine` (typed HttpClient for Ollama Cloud) returns the strict JSON contract. Missing API key → `OllamaConfigurationException` (`400`); transport/HTTP failure → `SignalGenerationException` (`502`).
7. **Deterministic post-processing (`BuildRun`).**
   - Iterate model picks in order; drop blanks/duplicates; **discard tickers not in the candidate set**; **discard picks without a thesis**; **discard picks carrying a hard trap flag**; **exclude resolved positions** (prior stop/target already touched).
   - Normalize the plan through `PseBoardLotService` (15-tier tick grid, `target > entry > stop`), then for `DAY` call `NormalizeTradePlanWithinStaticLimits` so entry/stop/target stay inside `FloorToTick(close*1.5)` / `CeilingToTick(close*0.7)`; `DAY` must also clear the **net R:R ≥ 2.0** gate after the per-leg round trip (`BuyLegFeeRate` 0.295% + `SellLegFeeRate` 0.395% = 0.690%).
   - Size the trade twice, on purpose: `PseBoardLotService.RoundSharesToBoardLot(100_000, entry)` keeps the legacy `BoardLotSize` / `BoardLotShares` pair for stored rows, while `OrderTicketCalculator.Build` (given the live account context, the name's 20-day turnover, the edge assessment and the sector/ADV dials) produces the authoritative `OrderTicketDto` the UI and the blotter consume. When the book cannot be read the run still publishes, just without tickets.
   - **Price the edge (server-owned).** `ProbabilisticEdgeService.EvaluateSetup` blends the shrunk empirical barrier hit rate with the ATR barrier geometry, applies bounded tilts (Weinstein stage, RS63d, VCP, breadth, regime, trap warnings, conviction), clamps to `[0.05, 0.95]`, then returns `NetRiskRewardRatio`, `BreakEvenWinRate`, `WinProbability`, `ExpectedValueR`, `QuarterKellyFraction` and the `EdgeVerdict` (`TRADE` / `SMALL_SIZE` / `WATCH_ONLY`). The model never supplies a probability.
   - **Pre-mortem is mandatory.** A short, actionable `bear_case` from the model is kept; otherwise `ResolveBearCase` writes a deterministic fallback naming the stop price, the resistance and the model's win probability.
   - **Server-verified citations:** keep only model citations that match a retrieved snippet `Reference` (e.g. `pse_rules#static-price-band`) or document slug, deduplicated, max 4.
   - **No top-up.** If nothing tradeable remains, `BuildRun` throws `SignalGenerationException` and nothing is persisted.
   - Recompute **drift** from prior rank (`NEW`/`UPGRADED`/`DOWNGRADED`/`HELD`) — never trust model drift.
   - Build **drops** for every prior ticker no longer chosen: price vs prior stop → `INVALIDATED`; price vs prior target → `TARGET_HIT`; else model category if valid; else `DISPLACED`.
   - **Run-level posture.** Count the verdicts and derive `RecommendedCashPct` from the regime (BEARISH 70 / NEUTRAL 40 / BULLISH 20), shifted by breadth bands and by `+(10 − actionable)*4`, clamped 0–100.
8. **Grade the ledger first.** Before persisting, `SignalOutcomeService.ResolveOpenSignalsAsync` walks stored `OPEN` picks, reads the real OHLC bars after the run date and writes `WIN_TARGET` / `LOSS_STOP` / `EXPIRED_WIN` / `EXPIRED_LOSS` with `OutcomeExitPrice`, `RealizedNetR` and `BarsHeld` (a same-session stop+target tie resolves to the stop).
9. **Persist atomically.** `ISignalRepository.SaveSignalRunAsync` replaces any existing run for the same `(RunDate, Horizon)` inside a transaction.
10. **Return DTO** enriched with that day's metrics, disclosures, odds, bear case and outcome state (`SignalRunMapper`). The mapper also attaches each pick's `WavePlan` (`WaveTradePlanCalculator.BuildPlan`), and the controller adds the run-wide `DirectionForecast` (`MarketDirectionService.Evaluate`) plus the `TrustPulse` (from the same scorecard the reader can open) — so a stored run re-renders with the same call, plans and ledger line it had on the day.

## Key design decisions / patterns

### Probabilistic edge, Quarter-Kelly sizing and the forward-outcome ledger
- **The desk, not the model, owns the odds.** `ProbabilisticEdgeService` (Application, pure) takes the plan geometry, the candidate's metric row, breadth and regime and produces `WinProbability`, `BreakEvenWinRate`, `ExpectedValueR`, `QuarterKellyFraction` and `EdgeVerdict`. `OllamaSignalOutput` carries no probability field; the prompt tells the model the desk owns sizing and asks only for a `bear_case` pre-mortem.
- **Fee math lives in Domain, and the two legs differ.** The stock transaction tax is charged on sales only — `0.10%` under RA 12214/CMEPA from `CmepaEffectiveDate = 2025-07-01`, `0.60%` before it — so `PseBoardLotService` publishes `BuyLegFeeRate = 0.00295m` (0.25% commission + 12% VAT + 0.005% PSE fee + 0.01% SCCP), `SellLegFeeRateOn(date)` (the same plus the tax in force) and `RoundTripFeeRateOn(date)` as their sum (0.00690 today, 0.01190 before the cut). Per share, `ComputeNetRewardPerShare` charges each leg on its own price (`target·sell + entry·buy`), `ComputeNetRiskPerShare` does the same on the way down, and `SplitRoundTripFee(rate, tradeDate)` keeps every caller that still passes a rate honest; per clip, the settled-peso `ComputeNetRiskPhp` / `ComputeNetRewardPhp` add the PHP 20 + 12% VAT commission floor, which is what the sizing and the verdict actually use. They drive `ComputeBreakEvenWinRate` (`netRisk / (netReward + netRisk)`), `ComputeExpectedValueR` (`p·netRR − (1 − p)`), `ComputeQuarterKellyFraction` (`max(0, (p·netRR − (1 − p)) / netRR) / 4`) and `ComputeEffectiveRoundTripFeeRate` (adds the tick spread used by the replay). `SignalOutcomeService.NetRealizedR` and `MoneyManagerTrainingService.NetRealizedR` charge the legs separately too. At entry 100 / stop 95 / target 110 on today's schedule the per-share constants are net risk 5.6703, net reward 9.2705, break-even win rate 0.3795 and 1,760 shares on a 1% of PHP 1M budget.
- **Probability is an estimate with a stated prior.** `ComputeEmpiricalBaseRate` counts historical ATR-shaped barrier hits from the stored bars, shrinks the result toward the 0.42 prior with 12 pseudo-observations and returns `null` under 60 bars; the barrier geometry (`netRisk / (netReward + netRisk)`) is blended 50/50 with it, then bounded tilts apply (Stage 2, RS63d > 0, VCP < 0.85, breadth ≥ 55%, regime, soft traps, conviction ≥ 80). Final clamp `[0.05, 0.95]`.
- **Verdict rule.** `EV ≤ 0` → `WATCH_ONLY`. `TRADE` requires net R:R ≥ the horizon minimum, EV ≥ the horizon minimum, `p ≥ breakEven + 0.05`, a non-BEARISH regime and no trap warnings; anything else positive is `SMALL_SIZE`. `WATCH_ONLY` names stay in the list for research context but carry zero risk-sized shares in the UI.
- **Pre-mortem is mandatory.** `ResolveBearCase` keeps a model pre-mortem when it is ≤ 30 words and names a level, otherwise writes "A close below PHP {stop} invalidates the trend setup … win probability of {p} is only a shrunk estimate."
- **Breadth is measured on the universe, not the Top 10.** `QuantitativeFilterService.ComputeMarketBreadth` reports % above 50D/200D and the Stage-2 count; `DailyMarketSnapshot`/`SignalRun` persist it and the prompt prints a `BREADTH:` header.
- **The ledger grades the desk, and it only grades positions that were actually opened.** `SignalOutcomeService.ResolveOpenSignalsAsync` re-reads real bars for every `OPEN` pick (bounded lookahead) and first looks for a **fill**: the pick is live from the first forward session whose `low <= EntryPrice` (`entryIndex`). No fill inside the horizon window writes `UNFILLED` with a null exit price and a null `RealizedNetR` — nothing was bought, so nothing is banked and nothing is counted as a loss. From the fill bar onward the stop is evaluated before the target, and the fill bar itself cannot bank the target (the entry only exists because price traded down to it). `OPEN` means the horizon window has not elapsed yet. `BuildScorecardAsync` aggregates win rate, expectancy in R, profit factor, Brier score, calibration buckets, per-verdict breakdown and the recent resolved list for `GET /api/signals/scorecard`; `UNFILLED` rows are excluded from every realized statistic and from `openCount`, which counts only `OPEN`; because `ResolveOpenSignalsAsync` re-reads only `OPEN` rows, `UNFILLED` is terminal — a pick the tape never filled is never graded twice. Brier and the buckets are computed over picks with `WinProbability > 0` only: a row persisted before the odds migration never made a forecast, so it still counts toward realized performance but cannot be graded for calibration.
- **Slippage is a cash debit, not a second return.** `BacktestService.ComputeSlippageCostPhp` charges the estimated entry slippage at the moment of the buy and refuses the trade unless `costPhp + slippageCostPhp <= cash`; the amount is persisted on `SimulatedPosition.SlippagePhp` and subtracted from the realized P&L, so the equity curve already carries it and `NetReturnAfterSlippagePct` must equal `NetReturnPct` (`BacktestTradeDto.SlippagePhp` publishes the per-trade charge). Charging it a second time as a percentage would double-count the same pesos.
- **Playbook:** `knowledge-base/playbooks/probabilistic_expectancy.md` documents the fee model, the verdict gates, the ledger maths and the "grade the rule, not the story" policy.

### Self-training money manager (closed loop)
- **One learned book per horizon.** `TrainedHorizonModel` stores a logistic fit (intercept + 12 factor weights + train-only means/scales) plus its held-out scores. `MoneyManagerTrainingService` builds the training set from the real tape: `BuildTrials` walks each ticker's prefix once, **simulates the desk's own execution** (`SimulateBarrier`: tick-grid plan, the effective round-trip fee, the +1R break-even ratchet, the +1.5R causal EMA20 trail, the causal index regime) and grades it with `NetRealizedR`, keeping only names clearing the PHP 5M turnover floor. A trial the desk could not have funded is not a training row.
- **The model learns a residual, not a rival.** `LogisticModelTrainer.Fit` takes a per-row `offset` and `sampleWeights`: the structural prior enters as `logit(prior)` and the weights explain only what the prior missed (`eta = logit(prior) + β₀ + w·z`). Trial weights are `1/√(signals that date)` (so one crowded session cannot outvote the tape) × `clamp(0.5 + 0.5·|RealizedR|, 0.5, 2.0)` (so a +3R winner is not averaged away by a +0.1R scratch), normalised to mean 1.
- **The split cannot peek.** Chronological 70/30 by entry date; training trades whose forward window had not cleared before the first held-out entry are purged, and `max(1, ForwardWindowBars)` **trading sessions** (`PseTradingSessionRules.TradingSessionsBetween`, holidays excluded) of embargo separate the slices. Standardisation uses training-slice means/scales only. The L2 strength is picked on a nested inner split before the held-out slice is read at all (see `SelectLambda` below).
- **Promotion is a gate, not a switch.** The fit is promoted only when the held-out slice holds `MinimumValidationTrials = 25` trades, the whole set holds `MinimumTrials = 80`, its Brier **beats** the neutral prior's on the same trades, its **log-loss does not exceed** the prior's, and `ComputePolicyExpectancyR` — the expectancy of the trades the model would actually have funded at `EV > 0` after friction — is positive. Calibration alone cannot promote: a fit that predicts well but funds losing trades stays out. Everything else is persisted as `PRIOR_FALLBACK` with the numbers that rejected it.
- **An unpromoted fit cannot price.** `LearnedEdgeModel.FromActive` returns `null` unless `IsActive`, so the live path is structurally unable to consume a rejected model. A promoted model adds `Tilt` — half its deviation from its own base rate, capped at ±6pp — after every structural tilt, and rescales the Quarter-Kelly stake by `fullKelly / 0.25`.
- **Kelly is stored as a fraction multiplier, never as account risk.** `OptimalKelly` funds only `EV > 0` trades and returns `clamp(c·f*, 0, 0.025)`; `NeutralKellyFraction = 0.25` is the "no opinion" value the governor divides by, so a stored multiplier of 0.5 means "half the usual stake", not "0.5% of equity". The replay uses the same convention with `KellyReferenceFraction = 0.02`.
- **The desk grades itself into the prompt.** `ComputeLiveCalibrationOffsetPctAsync` (≥20 graded picks, 20 pseudo-samples, ±10pp) corrects the claimed odds; `BuildDeskMemoryAsync` publishes the realized record, the sectors that paid/bled, the promoted model's factors and the latest stop-outs; `AppendDeskTrackRecord` prints `DESK_TRACK_RECORD_AND_LEARNED_EDGE` + `RECENT_STOP_OUTS`. All of it is computed from the stored ledger, never from model claims.
- **Refit never blocks a run.** `DailySignalSchedulerService` refits all four books after the week's first trading session in its own DI scope, logging failures; the pipeline's loaders swallow non-cancellation exceptions and fall back to the prior/zero offset. `ExecuteAsync` additionally queues a **`BootstrapRetrainAsync`** on `Task.Run` so a fresh database bootstraps itself, guarded by `NeedsBootstrap` — true only while a horizon is `UNTRAINED`, because a stored `PRIOR_FALLBACK` is a decision and must not be re-fitted on every restart. The training endpoints answer `503` on an empty feed instead of inventing data.
- **Playbook:** `knowledge-base/playbooks/asymmetric_wealth_compounding.md` (risk is a fraction of equity, the only legal pyramiding shape, the mechanical exit ladder).

### Server-owned order tickets and the paper blotter
- **One sizing engine.** `OrderTicketCalculator.Build(context, entry, stop, target, verdict, avgTurnover20dPhp)` returns `BoardLotSize`, `Shares`, `Lots`, `BuyOutlayPhp` (all-in with the buy leg), `NetRiskPhp` (settled pesos, commission floor + VAT included), `NetRewardPhp`, `BreakEvenStopPrice`, `RiskBudgetPhp`, `LiquidityCapped` and readable `Warnings`. It sizes from the risk budget, then caps by heat room, free cash, the single-position percentage and 2% of 20-day turnover, rounds down to whole board lots, and finally **steps lots down** while the settled risk still exceeds the budget — so the published size is one the account can actually carry, not one a per-share identity only pretended to fit. The risk fraction it starts from is the base × verdict × edge × volatility × drawdown, governor-clamped to `[0.50, 1.50]`, then × the `LiveDriftPolicy` multiplier. `WATCH_ONLY` always yields zero shares; `SMALL_SIZE` applies `SmallSizeRiskMultiplier`.
- **The browser never sizes.** Every `SignalItemDto` carries the ticket (built in `SignalRunMapper` from a **`BookSizingSnapshot`**), `TickerResearchDto` carries one, and `GET /api/portfolio/order-ticket` sizes an arbitrary plan. `lib/riskSizing.ts` renders those fields and marks `serverSized: false` only for runs stored before tickets existed.
- **One book read sizes the whole list.** `PortfolioService.GetBookSizingSnapshotAsync` reads the account, the open trades and the session's metrics **once** and returns a `BookSizingSnapshot` whose `For(ticker)` derives the exact `OrderTicketContext` that ticker deserves — its sector's exposure and name count, its own `AtrPct` for the slippage estimate, and its pyramid state (`ExistingUnrealizedR`, `ExistingStopAtBreakEven`, `ExistingPyramidCount`, `ExistingPositionCostPhp`) marked from the stored session. Before this, a run built one ticker-less context, so every pick was sized as if it were the first position in an empty book: no sector cap, no ATR slippage, no pyramid rules. `GetOrderTicketContextAsync(ticker, ct, horizon)` is now the thin single-ticker wrapper over it, and `GetOrderTicketAsync` takes the `EdgeAssessment` itself so the pesos and the Kelly stake are computed from one probability. The optional `horizon` is what makes the live-drift throttle per-book: without it the ticket is sized against the raw governor band.
- **The blotter is the only writer of cash.** `PortfolioService` owns every transition: `OpenTradeAsync` (board-lot, tick, free-cash, single-position and heat validation → `PortfolioRuleViolationException` → `400`), `UpdateStopAsync` (rejects a stop at or above the target), `CloseTradeAsync` (sell-leg proceeds, realized P&L and R, cash credit, double-close refusal), `TrimTradeAsync` (partial exit, see below) and `UpdateSettingsAsync` (percentage clamps; a capital change resets cash only on an empty book).
- **Only one pyramid shape is legal.** A ticket that names an already-open ticker is routed to `PyramidIntoOpenTradeAsync` instead of opening a second row: the add must enter **above** the existing entry (no averaging down or flat re-entry), the stop must already sit at the break-even tick, the position must be at least **+1R** unrealized (marked from the latest stored session, never from the ticket's own entry), the add count must be below `MaxPyramidAdds = 2`, the entry must sit below the target, and cash/position-cap/heat still apply. Sized adds use `PyramidRiskMultipliers` (0.50x then 0.25x of the normal risk). The merge averages the entry on the **fee-paid** cost, sums `BuyCostPhp`, recomputes `InitialNetRiskPhp` against the ratcheted stop, increments `PyramidCount` and appends a note — one position, one cash debit.
- **A trim is a real partial exit, not a resize.** `TrimTradeAsync` requires 0 < shares < the true share count and **whole board lots on both legs** (the slice at the exit price, the remainder at the entry price). The slice carries its proportional share of `BuyCostPhp` and `InitialNetRiskPhp`, so the blended R of every slice reproduces the position's own result; it is persisted as its own `CLOSED` row (with its own `RealizedNetR` and a note) while the remainder keeps running. Cash is credited with the net sell proceeds, and banking above the break-even tick ratchets the remainder's stop up to it — the free ride. `RecommendedTrimShares` is computed server-side by `ComputeRecommendedTrimShares` as **the largest slice at or below half that satisfies both legs at the marked price**, so the offered quantity is always one `POST /api/portfolio/trades/{id}/trim` will accept (PSE lots coarsen as a price falls, so the entry lot alone is not enough); 0 means no legal trim exists and the UI hides the button.
- **The book grades itself in R.** `GetSummaryAsync` publishes `ExpectancyR` (average realized R per settled trade), `ProfitFactor` (gross winning R ÷ gross losing R) and `PayoffRatio` (average winner ÷ average loser), all computed from the closed ledger — the UI formats them, never recomputes them.
- **Marks are honest.** `LoadMarkToMarketAsync` walks the last `MarkLookbackSessions` stored snapshots for the position's ticker; when the name has not printed since entry, `FallbackMark` marks it at the entry price with `HasSession: false`, and `ResolveAction` only reports `STOP_BREACHED` / `TARGET_REACHED` for a session that was actually observed.
- **Exit ladder** (`ResolveAction`, most urgent first): stopped through `CurrentStopLoss`, target reached, `MOVE_STOP_TO_BREAKEVEN` at ≥ +1R (fee-paid), `TRAIL_STOP_EMA20` at ≥ +1.5R when EMA20 sits above the stop, `TIME_STOP_DUE` at the horizon's forward window, else `HOLD`.

### Pod-shop risk governance, sector rotation and transaction costs
- **Four multipliers, one clamp.** `OrderTicketCalculator` multiplies the base risk fraction by: the verdict (`SMALL_SIZE` → `SmallSizeRiskMultiplier`, `WATCH_ONLY` → 0), the **edge** (`QuarterKellyFraction / KellyReferenceFraction = 2%`, via `GovernorMultiplier`), the **volatility regime** (`min(1, TargetAnnualVolPct / RegimeVolPct)` — volatility targeting only cuts) and the **drawdown** (`NORMAL` → 1.0, `DEFENSIVE` between the soft/hard thresholds → down to `MinGovernorMultiplier`, `HALTED` past the hard one → 0 shares with `RiskGovernorState.Halted`). `GovernorMultiplier` clamps to `[0.50, 1.50]` and rounds to two decimals so the published size is reproducible.
- **Book-level caps run before the shares are funded.** `OrderTicketContext` carries the sector name, the sector's current exposure and position count, the account's caps and the existing entry price; the calculator refuses a **sector at its name limit**, cuts the order to the **remaining sector room**, and refuses to **average down** an open position. A legal pyramid add (`ExistingUnrealizedR ≥ 1`, `ExistingStopAtBreakEven`, `ExistingPyramidCount < 2`, entry above the existing one) is exempt from the sector *name count* because it does not add a name, and `MaxPositionPct` is measured against equity **net of committed cost**. Every block publishes an explicit reason. `BookSizingSnapshot.For(ticker)` builds that context from the stored book plus the latest snapshot (`PseiRealizedVol20dPct` feeds the volatility dial, the name's own `AtrPct` feeds the slippage estimate).
- **Transaction-cost analysis on every clip.** `PseBoardLotService` gained `ComputeTickSpreadRate` / `ComputeAdvParticipationRate` / `ComputeEstimatedSlippageRate` (`2 × tick / price` round-trip spread plus a square-root market-impact term capped at `MaxMarketImpactRate = 1.5%`) and `ComputeEffectiveRoundTripFeeRate`, which `ProbabilisticEdgeService` charges when a slippage rate is supplied. The ticket publishes `SlippageRatePct`, `EstimatedSlippagePhp`, fee-plus-slippage net risk/reward, `AdvParticipationPct` and `ExecutionGuidance` (`LIQUID_MARKETABLE` / `STAGED_ENTRY` / `LIMIT_ONLY` / `WORK_THE_ORDER` / `NO_TRADE`).
- **Drawdown is state, not a parameter.** `PortfolioService.GetSummaryAsync` lazily seeds `PeakEquityPhp`, raises it on a new high, persists it, and derives `DrawdownPct` + `RiskPosture` (`Normal`/`Defensive`/`Halted`) plus `SectorExposure` cards; heat, drawdown and sector breaches become `Alerts` strings the terminal banners.
- **Sector rotation is a pure function of the session.** `SectorRotationService.Compute(metrics)` groups by `Sector`, scores breadth (0.30), Weinstein Stage-2 share (0.25), 63D relative strength (0.30) and 20D up/down volume (0.15), **renormalises over the components the sector actually reports**, and labels `LEADING` (≥70) / `IMPROVING` (≥55) / `WEAKENING` (≥40) / `LAGGING`. `QuadrantMap`/`QuadrantFor` expose lookups for the prompt, the picks and research. The pipeline always recomputes it for the run and only persists `SectorRotationJson` when the stored session has none, so a re-run of an old session stays consistent with its own metrics.
- **The factor sleeve is priced once per horizon.** `ProbabilisticEdgeService.ComputeHorizonBaseRates` builds the ATR and 50D series **once** and grades DAY/WEEK/MONTH/YEAR barriers in one sweep (previously four quadratic passes). `QuantitativeFilterService` adds `ComputeUpDownVolumeRatio`, `ComputeChaikinMoneyFlow`, `ComputeTrendEfficiency`, `ComputeBeta` (date-matched, ≥60 overlapping returns), `ComputeMaxDrawdownPct` and `ComputeRealizedVolatilityPct`.

### Point-in-time data, calibrated validation and live drift throttling
- **History is replayed with the friction of its own date.** `PseBoardLotService.StockTransactionTaxRate(tradeDate)` returns the pre-CMEPA `0.60%` sale tax before `CmepaEffectiveDate = 2025-07-01` and `0.10%` from it, and `BuyLegFeeRate` / `SellLegFeeRateOn(date)` / `RoundTripFeeRateOn(date)` / `SplitRoundTripFee(rate, tradeDate)` / `ComputeBuyTotalCostPhp(..., tradeDate)` / `ComputeSellNetProceedsPhp(..., tradeDate)` / `ComputeRealizedNetPnlPhp(..., entryDate, exitDate)` / `ComputeInitialNetRiskPhp(..., tradeDate)` / `ComputeEffectiveRoundTripFeeRate(..., tradeDate)` all take the date. `MoneyManagerTrainingService.SimulateBarrier` and `BacktestService` (candidates, labels, fills, marks, fees) pass the session date, so a 2023 trade pays the tax that existed in 2023; only the live promotion gate uses today's schedule, because that is the schedule a live clip actually faces.
- **The commission floor makes risk non-linear.** `MinimumBrokerCommissionPhp = 20` with `CommissionVatRate = 0.12` binds whenever one leg's gross is under roughly `PHP 8,000`, so `ComputeNetRiskPhp` / `ComputeNetRewardPhp` / `ComputeNetRiskRewardPeso` measure the settled pesos (per leg, floored and VAT'd) instead of `shares × per-share spread`. `OrderTicketCalculator` therefore steps **whole board lots down** until the settled risk fits `RiskBudgetPhp`, and refuses the ticket outright when a single lot already exceeds the budget; `PseBoardLotService.ComputeLegFeePhp(shares, price, isSell, tradeDate)` is the one implementation.
- **Stops fill where the tape would have filled them.** `ResolveStopFillPrice(stop, open, low)` returns the open when the session gapped through the stop and the stop itself when it merely traded through it; the replay, the training labels and the outcome resolver all use it, while targets keep crediting their own level. `PseTradingSessionRules.TradingSessionsBetween` (holidays excluded) replaced the weekend-only embargo count.
- **A replay may not read today's tape.** `QuantitativeFilterService.EvaluateStock(..., includeLiveForeignFlow: false)` drops the live `NetForeignTodayPhp` print, and `ScopeToSession` / `IsAvailableBy` / `ScopeDisclosures` drop filings dated after the session or timestamped after the `PseTradingSessionRules.MarketClose` cutoff on the same day (`StockDisclosure.FiledAtPht`, optional; an unreported time on a same-day filing still counts as available). Both the trainer and the backtester pass `false` and rely on the scoped disclosures.
- **Liquidity is judged on the median, not the mean.** `StockDailyMetric.MedianTurnover20dPhp` and `ActiveTradingDays20d` are computed in `EvaluateStock` (`ComputeMedianTurnover20d` over the last 20 sessions) and persisted, and `MeetsLiquidityFloor(avg, median, activeDays, ...)` requires the mean **and** the median to clear `LiquidityFloorPhp` plus `MinimumActiveTradingDays20d = 16` sessions that actually printed volume. A row written before those columns existed reports `0`/`0` and falls back to the mean, so history is never rejected by a column that did not exist.
- **The volume gate belongs to the horizon.** `HorizonProfile.MinimumVolumeRatio` is `1.2` on `DAY`, `1.2` on `WEEK`, `1.1` on `MONTH` and `1.0` on `YEAR`, and both `BacktestService.IsEligible` and `MoneyManagerTrainingService.IsEligible` read it; the trainer's cheap prefix prefilter uses the loosest ratio as a shortcut only.
- **Hyper-parameters are chosen without looking at the promotion slice.** `MoneyManagerTrainingService.SelectLambda` scans the L2 grid on an **inner** chronological split of the training slice (`InnerTrainFraction = 0.80`, same forward-window purge), refits the winner on the whole training slice, and only then touches the held-out slice for the Brier/log-loss/`policyExpectancyR` gate. When the inner slices are thinner than `MinimumTrainingTrialsForFit` / `MinimumValidationTrials` it returns the strongest λ instead of peeking.
- **Live drift throttles new risk after every clamp, and the verdict is persisted.** `LiveDriftPolicy.Classify` reads the **rolling** record of the last `LiveDriftSnapshot.WindowPicks = 30` graded picks, requires `MinimumGradedPicks = 15`, compares the win-rate gap in **percentage points** against `max(20pp, 2 SE)` and the expectancy gap against `max(0.60R, 2 SE / √n)`, and keeps a released throttle on until both gaps halve (hysteresis). `SignalOutcomeService.EvaluateLiveDriftAsync(horizon)` is the only caller: it compares the window against the record the model was **promoted** on (`ValidationWinRate` / `ValidationExpectancyR`), persists the verdict on `TrainedHorizonModel.LiveDrift` / `LiveDriftGradedPicks` only when it changed, and returns a `LiveDriftSnapshot` with both gaps and the `Describe` reason. A book priced off the structural prior has no promoted record to drift from, so it stays `STABLE` (the calibration offset already handles the prior's own error). `PortfolioService.GetBookSizingSnapshotAsync(ct, horizon)` evaluates it once per book and `BookSizingSnapshot.For(ticker)` stamps every ticket's `OrderTicketContext`; a ledger failure logs and leaves the ticket unthrottled rather than failing the cash page. `OrderTicketCalculator` multiplies the risk fraction by `MultiplierFor` (1.00 / 0.65 / 0.35 / 0.00) **after** the `[0.50, 1.50]` governor clamp, so `HALTED` really sizes zero shares.

### On-demand research and the causal replay
- **Research reuses the daily engine, never a second one.** `TickerResearchService` fetches one `{TICKER}.PS` chart through `IMarketDataProvider.FetchSingleStockAsync`, falls back to the latest stored metric, then runs the same `QuantitativeFilterService.EvaluateStock`, horizon ATR plan (`NormalizeTradePlan`, static-band clamped for `DAY`), `ProbabilisticEdgeService` and `OrderTicketCalculator`. It echoes `DataSource` (`live`/`stored`), the stored row's own `AsOfDate`, catalog membership through `IMarketDataProvider.IsTracked` (the catalog lives in Infrastructure, so Application asks instead of referencing it) and the liquidity-floor verdict; optional AI prose never owns a level. It also returns the same `WavePlan` the daily run would build, and — when the caller supplies `averageCost` (+ optional `shares`) — a `PositionAdvice` from `WaveTradePlanCalculator.EvaluateHolding`, so the "already holding it" tab is the identical arithmetic the blotter would use. **It is priced like the run**: the published learned model plus the live calibration offset are loaded, the regime is resolved causally from the fetched PSEi bars, and the ticket takes the same `EdgeAssessment` and sizes it against `ResearchSizingNotionalPhp = 50_000` for the slippage estimate.
- **The replay is an account, not a single idea.** `BacktestService` walks the series bar by bar, evaluates each session on the prefix that preceded it (empirical base rate disabled — it would read future bars), and holds a **multi-slot book**: `MaxOpenPositions = 5` concurrent clips, `MaxPositionsPerSector = 2` and `MaxSectorExposurePct = 35` of equity per sector, `MaxPortfolioHeatPct = 6` of equity in open risk, and `RiskPerTradePct` scaled by the drawdown governor, the verdict (`SmallSizeRiskMultiplier = 0.50` when `EV < 0.25R`) and the Kelly dial. Size comes from **equity**; cash is only a funding check — an unaffordable clip is trimmed to the whole lots `cash / (entry × (1 + buy leg) × (1 + slippage))` can settle, or dropped, so the book is never overdrawn. Same-bar stop+target ties resolve to the stop, the round trip pays fees **plus** the board-lot slippage debit, and nothing is funded unless `BuildCandidate` clears **1.2R after fees** and the model's `EV > 0`.
  - **Drawdown governor.** `ComputeDrawdownRiskMultiplier` halves the clip below the soft 5% curve drawdown and stops funding at the hard 10%, mirroring the live book's `RiskPosture`. Every clip is funded from the **marked** equity, so a losing book automatically sizes smaller.
  - **Exit ladder.** `RatchetStop`: at +1R the stop jumps to the fee-paid break-even tick, at +1.5R it trails to `EMA20` (built causally per ticker/date by `BuildCausalEma20`), and it may never sit above the target. Exits therefore report `STOP`, `TARGET`, `TIME`, `BREAKEVEN` or `TRAIL_EMA20`. `LabelOutcome` grades each candidate through the same ladder, so the replay's model is trained on the exits it would actually take.
  - **Benchmark + risk-adjusted return.** The equity curve carries `BenchmarkEquityPhp` (the same starting capital held in `PSEI.PS` from the first replayed session, built causally from `indexBars`), and the result adds `BenchmarkReturnPct`, `ExcessReturnPct` (alpha = slippage-adjusted net return − index), `CagrPct`, `AnnualizedSharpeRatio` (null under 20 sessions), `CalmarRatio`, `TotalSlippagePhp` and `NetReturnAfterSlippagePct`. The desk pays friction the benchmark does not, so a positive alpha is conservative evidence. `GET /api/signals/backtest` still answers `503` rather than inventing history.
- **The regime dial is priced from the tape, not the label.** `ResolveIndexRegime` reads the closed index prefix (null below `RegimeBarRequirement`), `IsBearishIndexSession` blocks a new long when it closed **under both SMA50 and SMA200**, and `TickerResearchService` runs the same resolution over the bars it just fetched so a single-name lookup cannot quote a stale stored regime.
- **The replay refits its own model, causally.** A nested `WalkForwardEdge` is refitted every `WalkForwardRefitSessions = 60` sessions using only candidates whose `OutcomeDate` had already passed, learns the same residual (`logit(prior)` offset, fixed λ = 25, cluster weights) and is used for pricing/sizing **only** when it beats the neutral base rate on its own resolved trades and has `MinimumWalkForwardTrials = 40` of them; otherwise the structural prior prices the clip. It never writes `TrainedHorizonModels` — promotion to live pricing stays with `MoneyManagerTrainingService` — and its acceptance test is deliberately in-sample, so a replay's alpha should always be compared against a prior-pinned baseline.


### Dual-model Ollama strategy (live-only)
- `IOllamaSignalEngine` is the abstraction; the only implementation is `OllamaSignalEngine`.
- `OllamaSignalEngine` is a typed HTTP client against Ollama Cloud `/api/chat` with `format: json`, `temperature: 0.1`, one corrective retry carrying parser errors. It prints the retrieved playbooks into the system prompt and lists the exact `reference` ids the model may cite.
- **The prompt hands the odds to the server.** Rules 12–13 state that the desk — not the model — owns probability, position size and the actionability verdict, require a `bear_case` pre-mortem (≤ 30 words naming a level) and require `bear_case` in the JSON contract. The system prompt also carries CROSS-ASSET and FOREIGN FLOW bullets ("n/a means unreported, never zero"). The user prompt prints a `CROSS-ASSET: US 10Y … (20d …bps) | Brent … | EPHE …` line, a `BREADTH:` header, the net foreign figure **with its provenance suffix**, plus per-candidate `probability inputs: RS63 … | ATR14 … | VCP … | historical hit rate …`, with `n/a` when a factor is unavailable (never a fabricated zero).
- `OllamaCloudOptions.FastExtractionModel` (`glm-5.3-flash`) powers a compact, cheap pre-extraction pass (disclosures/traps summary per session); a blank value skips the pass entirely.
- **A model the endpoint does not serve disables the fast pass instead of failing the run.** `SendChatAsync` raises an internal `ChatResponseException(status, message)`; `SendRankingChatAsync` converts it back to `SignalGenerationException` (the ranking `502` contract is unchanged), and `EnrichWithFastExtractionAsync` treats `404` as a configuration error: one warning naming the setting and the reasoning model, then `_fastExtractionUnavailable` latches the pass off for the life of the engine. Any other fast-pass failure keeps the old "log and continue without a note" behaviour.
- `OllamaCloudOptions.EmbeddingModel` (`nomic-embed-text`) vectorises knowledge chunks through `OllamaEmbeddingClient`; a blank value leaves retrieval on the lexical path.
- `OllamaCloudOptions.EnableOfflineFallback`, `OfflineSignalEngine`, `SignalEngineRouter`, `TradePlanBuilder`, `IDemoDataSeeder`, `DemoDataSeeder` and `DemoMarketDataFactory` were **deleted**. There is no offline ranking path and no demo tape.

### Knowledge base (SQLite RAG)
- **Content:** `backend/knowledge-base/` — `pse_rules.md` (mandatory guardrails: 15-tier board lots, static band, fee drag, disclosure traps, Weinstein stages, risk rules) plus six playbooks (`day_week_momentum_vcp.md`, `day_week_risk_sizing.md`, `month_year_quality_value.md`, `month_year_ph_macro_sectors.md`, `probabilistic_expectancy.md`, `asymmetric_wealth_compounding.md`) and `docs/engineering-references.md` — 8 documents / 46 sections in the seeded library. - **Ingestion:** `KnowledgeBaseInitializer : IHostedService` runs `IndexBuiltInAsync` at startup (guarded by `KnowledgeBase:IndexOnStartup`, failures logged and swallowed); `POST /api/knowledge/reindex` is the manual equivalent. Deletes cascade.

Without an embedding model (or when the Ollama call fails) the path stays lexical + tag-based — retrieval never throws at the pipeline.

The request must carry `confirmRightsAndCloudProcessing=true` (default `false`, so absence is a `400`): indexing and retrieval both copy the text into prompts sent to the model provider, so the operator asserts the rights before it is stored.

### Compliance posture and the first-run legal gate
- **The API cannot be served to other people by accident.** `Infrastructure/Configuration/ComplianceOptions` + `WebApi/Middleware/ComplianceGuardMiddleware` default to `Compliance:DeploymentMode = PersonalLocal`: every non-loopback caller is answered `403` ProblemDetails before it reaches a controller (a `null` remote address counts as loopback so the in-memory test host works, and `/health` always passes). `LicensedCommercial` — an explicit operator assertion that the PSE market-data/redistribution agreement and the SEC licences exist — flips that check off and requires `X-PseDesk-Key` matching `Compliance:OperatorApiKey` / `PSEDESK_OPERATOR_API_KEY` on `POST`/`PUT`/`PATCH`/`DELETE`, compared with `CryptographicOperations.FixedTimeEquals` (401 on a mismatch, 503 when licensed with no key). `AllowedHosts` is the loopback allowlist, never `*`. Because that default makes a licensed deployment under a real host name answer `400` to everything, `Compliance:AllowedHosts` (a single host string) replaces it **only** when `DeploymentMode` is `LicensedCommercial` — applied to configuration in `Program.cs` before `builder.Build()`, so a leftover value can never widen the personal desk.
- **Honest outbound identity.** `MarketData:UserAgent` (`PseSignalDesk-PersonalResearch/0.1 (local-noncommercial)`) is sent to Yahoo and PSE Edge instead of a spoofed browser string; the DQR templates are documented as entitled-endpoints-only.
- **No solicitation, and simulated results say so.** Prompt rules 10/13 demand neutral third-person posture, no imperatives and no guaranteed outcomes; the UI calls the order box a research ticket, renames "Take trade" to "Record in blotter", and labels the replay's CAGR "Simulated · annualised · not a forecast".
- **One summary, four documents, one licence.** `LICENSE` (personal, non-commercial, all rights reserved — it carries the warranty disclaimer and the liability cap so the terms travel with a copy), `DISCLAIMER.md`, `PRIVACY.md` and `THIRD_PARTY_NOTICES.md` are the long form; `lib/legalConsent.ts` mirrors them in the un-dismissable first-run gate (`CURRENT_LEGAL_VERSION = '2026-11-v2'`, stored in `psedesk.legalAcceptedVersion`), and bumping that string re-prompts every browser. `DISCLAIMER.md` §7 is the one rule no code can enforce: the instruction-shaped Simple-mode copy ("buy in this band", "cut here", "lock break-even at +1R") is written for one self-user, so passing the output on as advice or running someone else's money through the blotter is out of scope and can make the operator an unregistered adviser under RA 8799. There are still no user accounts, roles or per-document ownership — the loopback guard and the operator key are the whole access story.

### Live market data provider
`PseMarketDataProvider` (typed `HttpClient`, honest `MarketData:UserAgent` instead of a spoofed browser string, options bound from `MarketData`):
- **The index is resolved, never assumed.** `ResolveIndexAsync` walks `MarketData:IndexYahooSymbols` (`PSEI.PS`) and takes the first symbol with a usable multi-bar chart (≥200 live bars, fetched with `dropZeroVolume: true`, session within `MaxSessionLagDays` (7) of the requested date). When no index symbol has history — Yahoo routinely answers `PSEI.PS` with one bar and a price, not a 200-session series — it falls back to an **equal-weight proxy** built from `MarketData:IndexProxyConstituents` (12 heavyweights: TEL, SM, SMPH, ALI, BDO, BPI, ICT, JFC, MER, AC, URC, GLO). The proxy is scale-free: it can drive the regime, breadth and realized volatility, but it never prints an index level (`PseiClose = 0`) or a PSEi moving average (`PseiSma50/Sma200 = 0`, i.e. unreported) and `RegimeNote` says "proxy". The **effective session date is the newest bar of whichever series resolved**, not the requested calendar day.
- **Both symbol lists are read through one normalised view.** The configuration binder *appends* a section onto the lists the options class already initializes, so a deployed `appsettings.json` that repeats the defaults would fetch `PSEI.PS` twice and build the proxy from 24 entries for 12 names. `MarketDataOptions.Normalize()` (`Program.cs` `PostConfigure`) and the provider's own constructor both run `DistinctNonBlank` (trim, drop blanks, case-insensitive first-wins), so the run, the per-URL cache and the `… of N constituents` diagnostic all see distinct symbols only. Each proxy constituent reports a `ProxyConstituentFetch(bars, reason)` and the reasons are appended after `Task.WhenAll` in configured order — never by parallel tasks into one `List<T>` — and `JoinReasons` trims the period each reason already ends with.
- **Two hosts, one payload.** Every chart GET tries `MarketData:YahooFinanceBaseUrl` and retries once on `MarketData:YahooFinanceFallbackBaseUrl` after a transport error, timeout or 5xx; a `404` is host-independent ("symbol not published") and is not retried. A zero-volume echo bar is dropped, so a stale quote can never date a session.
- `FetchUsdPhpAsync("PHP=X")` → needs a real close within 7 days of that session, else 503. Its `Sma50` and `Change20dPct` travel with the batch (`UsdPhpSma50`, `UsdPhpChange20dPct`).
- The PSEi series also yields `PseiRealizedVol20dPct` (`ComputeRealizedVolatilityPct` over the index closes) — the macro dial the ticket governor reads.
- `FetchDisclosuresAsync` → scrapes `edge.pse.com.ph/announcements/search.ax`; non-2xx/empty/timeout is 503; a successful page with no matching headline yields empty lists.
- **A filing belongs to the row that names its company.** Disclosure attribution is row-aware (date / company / subject cells are parsed together, company names are matched on word boundaries), so `DITO` is never matched inside "au**dito**r" and `BPI` is never matched inside "Phili**ppi**ne"; a headline is attached only to the ticker whose own row names it.
- `FetchStocksAsync` → `{TICKER}.PS` charts with `SemaphoreSlim` concurrency (`MaxConcurrency`), skipping symbols with a 404, <200 bars or no bar on the session date (warning); **<10 survivors → 503**.
- `ParseChart` reads `chart.result[0].timestamp` + `indicators.quote[0]`, drops `date > tradeDate`, and tick-rounds every OHLC via `PseBoardLotService` while re-establishing high/low containment.
- Timeouts use a linked `CancellationTokenSource`; a caller cancellation is rethrown untouched, its own timeout becomes 503.
- **Cross-asset dials are best-effort.** After the tape is fetched, `FetchMacroBenchmarksAsync` reads `MarketData:Us10YahooSymbol` (`^TNX`), `BrentYahooSymbol` (`BZ=F`) and `EpheYahooSymbol` (`EPHE`) concurrently through `TryFetchMacroSeriesAsync` (`FetchChartAsync` with `roundToTick: false`, every exception logged and turned into `null`) and `ReadMacroValue` (latest close + 20-session change; **yields in bps**, the rest in %; closes older than `MaxSessionLagDays` or non-positive report `null`). A macro outage never fails a run — it just leaves the tile `—`.
- **Foreign flow comes from the official DQR when one is reachable.** `TryFetchQuotationReportAsync` walks `MarketData:PseDailyQuotationUrlTemplates` (tokens `{yyyy}`, `{MMddyyyy}`, `{MMddyy}`), continues past 404/410/non-2xx/unparseable responses and returns `null` when nothing parses. `ApplyQuotationReport` overlays per-ticker `NetForeignTodayPhp` for the tickers the report names, appends a synthetic `PSE DQR` suspension disclosure for halted names (deduped per session, classified as the hard trap `TRADING_HALT_RISK`) and leaves every other ticker `null`; the batch then records `ForeignFlowSource = "pse-dqr-live"` and `Source = "yahoo-finance+pse-edge+pse-dqr"`.
- `NetForeignFlowPhp` / `NetForeignTodayPhp` stay `null` unless a DQR was parsed, and `ForeignFlowSource` is the provenance (`pse-dqr-live`, `pse-dqr-upload`, else `null`); the regime note names the source or says the flow is unreported.

### PSE Edge daily history (the Yahoo delisting fallback)

- **Why it exists.** Yahoo stopped publishing PSE equities: every `{TICKER}.PS` answers `404` ("No data found, symbol may be delisted") and `PSEI.PS` keeps only a sparse legacy series plus a live `regularMarketPrice`, so a run that trusted Yahoo alone could never build a session again. PSE Edge — the host the desk already scrapes for disclosures — still publishes the exchange's own daily bars per security, so the live-only contract survives without inventing a tape.
- **`PseEdgeHistorySource`** (Infrastructure, `internal`) makes three calls per symbol and reuses `MarketDataCache` for each: symbol search (`?term=TICKER` → `cmpyId`, matched on the exchange symbol, never on a fuzzy name), company page (`?cmpy_id=N` → `security_id`, exact symbol first so a preferred series cannot be picked for the common), and a `POST common/DisclosureCht.ax` with `{cmpy_id, security_id, startDate, endDate}` → `chartData[{OPEN,HIGH,LOW,CLOSE,VALUE,CHART_DATE}]` covering three to five years.
- **A failure is a reason, never an exception.** `FetchDailyBarsAsync` returns `EdgeBarFetch(Bars, Failure)`; every transport/HTTP/parse problem becomes a string that the provider composes next to whatever Yahoo answered, so one dark symbol cannot abort a run.
- **`WithEdgeHistoryAsync` is the seam.** It is called at exactly three points — the single-symbol research fetch, the stock fan-out and the proxy constituent fetch — and only replaces a chart that is unavailable or shorter than the caller's requirement (`MinimumStockBars` / `MinimumIndexBars`). A replacement clears `SymbolUnavailable`, keeps the caller's parsed window, and logs `Reading {TICKER} from PSE Edge ({n} daily bars) because …`. When Edge also falls short the reason carries both feeds and the short series' own size (`… PSE Edge: 160 bar(s), newest 2026-06-01.`), because a blank reason tells an operator nothing.
- **Volume is derived, because Edge reports peso value.** `VALUE / ((HIGH+LOW+CLOSE)/3)` lands within ~0.01% of the exchange's own share count on a real print and keeps `Close × Volume` equal to the official turnover the PHP 5M floor is measured on. Sessions are de-duplicated (last print wins), clamped to the requested window, and an OHLC row that is missing or non-positive is skipped rather than carried forward.
- **`MarketData:EnablePseEdgeHistory = false`** restores the strict Yahoo-only contract (and the old `503`), which is what `PseMarketDataProviderTests.EnablePseEdgeHistory_false_keeps_the_strict_yahoo_only_contract` pins.
- **Nothing on Edge carries an index series.** `psei/form.do` is a company-news search and `index/form.do` a company lookup; the symbol search answers `[]` for `PSEI`, so the PSEi index has no daily history anywhere and the equal-weight proxy of 12 heavyweights (now fed by Edge bars) remains the only live path for regime, breadth and realised volatility.


- **The downloaded body is cached, not the parsed object.** `MarketDataCache` (Infrastructure, registered as a **singleton**, `TimeProvider`-injectable, bounded at `DefaultMaxEntries = 200`) keys a Yahoo chart on `chart:{absolute chart URL}` for 10 minutes and an Edge page on `edge:{page URL}` for 5. Because the key is the full request URI, the `(symbol, window)` variants separate by construction, while `roundToTick` / `dropZeroVolume` / `tradeDate` stay per-caller (parsing runs on every call). The daily run, a replay and the research panel therefore share one download of the same chart instead of three.
- **Three guarantees, each with a test.** (1) Concurrent identical callers share a single HTTP call — the *task* is published before the factory starts (`TaskCompletionSource`), so nobody can observe a half-built entry. (2) A failure is never served: the failing entry is removed (only if it is still the same instance) before the exception reaches any caller, so the next run retries upstream. (3) The shared download runs on `CancellationToken.None` and every caller waits with `Task.WaitAsync(token)`, while `GetChartBodyAsync` / `DownloadDisclosureHtmlAsync` apply their own linked `RequestTimeoutSeconds` timeout — one abandoned browser tab can neither cancel nor poison a download another request is waiting for. Oldest `CreatedAt` entries are evicted past the bound, and eviction **skips an entry whose value a concurrent `Clear()` already removed** instead of dereferencing it (dereferencing it was a real `NullReferenceException` under the Edge fallback's cache traffic; `MarketDataCacheTests.GetOrAddAsync_evicts_safely_while_another_caller_clears_the_map` pins it).
- **`InvalidateCache()` is a default interface method** on `IMarketDataProvider` (no-op), implemented by the provider as `_cache.Clear()`; `SignalsController.RunNow` calls it so an operator-triggered run always sees the newest tape. Replay, research and scheduled runs deliberately reuse the warm cache.
- **One fan-out per session.** `FetchAsync` resolves the index first (its newest bar decides the session date), then starts `FetchUsdPhpAsync`, `FetchDisclosuresAsync`, `TryFetchQuotationReportAsync`, `FetchMacroBenchmarksAsync` and `FetchStocksAsync` **together** and `Task.WhenAll`s the set. `FetchStocksAsync` / `FetchStockAsync` take the disclosure `Task<IReadOnlyDictionary<…>>`, not its value, so each ticker awaits headlines only after its own chart has landed — a slow Edge page no longer serialises 24 chart downloads.
- **Disclosure failures are classified by the caller, not by a flag.** `DownloadDisclosureHtmlAsync` performs the GET and always throws `MarketDataUnavailableException` (so the cache never stores a non-page); `FetchDisclosureHtmlAsync` is the cached wrapper; `TryFetchDisclosureHtmlAsync` is the best-effort wrapper that logs and returns `null` for the extra pages. The old `throwOnFailure` parameter is gone.
- **The socket layer is pooled and compressed.** `AddHttpClient<PseMarketDataProvider>` installs a `SocketsHttpHandler` (`AutomaticDecompression = All`, `UseCookies = false`, `PooledConnectionLifetime = 5 min`), and `GET /api/research/catalog` carries `[ResponseCache(Duration = 3600, Location = Client)]` because the catalog is static metadata.

### Official DQR foreign flow and cross-asset macro dials
- **Two ingestion paths, one contract.** Live: `PseMarketDataProvider.TryFetchQuotationReportAsync` (configured templates, best-effort, provenance `pse-dqr-live`). Manual: `POST /api/signals/quotation-report` → `DailyQuotationImportService.ApplyAsync` (multipart `file` + optional `date`, 25 MB, `.pdf/.csv/.txt/.tsv`, provenance `pse-dqr-upload`). Both go through the same `IDailyQuotationParser` and write only what the report states.
- **The parser is deterministic and total.** `PseDailyQuotationParser` extracts text (PdfPig for PDFs), finds the header row, maps columns by name (`ticker`/`security`, `net foreign`, `value`, `close`), normalises accounting negatives (`(1,234.50)`), marks `SUSPEND`/`SUSPENDED` rows (whole-row scan when no status column exists), ignores untracked tickers and returns `ParsedDailyQuotationReport.Empty` for garbage. `HasData` is the only "did this parse" signal — no partial rows are ever invented. **A missing-marker cell keeps its column.** `CollectColumns` treats `-`, `--`, `—`, `–`, `N/A`/`NA`/`n/a`/`nil` after the numeric block as an explicit *null column* instead of dropping it, and `TryAddRow` skips a row whose **last** column (net foreign) is null. Before that fix a `-` in the turnover column shifted everything left and the turnover was stored as foreign flow; there is a regression test (`Parse_keeps_a_missing_marker_in_its_own_column`) for it.
- **The upload owns foreign flow, nothing else.** `DailyQuotationImportService` requires an already-stored session (`MarketSessionNotFoundException` → 404), rebuilds the batch with `MarketDataMapper.ToBatch(snapshot)`, overlays `NetForeignFlowPhp` + `ForeignFlowSource` + matched `NetForeignTodayPhp`, recomputes `QuantPreScore` only for rows it changed (so the 15-point pillar turns on without touching untouched names) and re-saves. Breadth, macro dials, FX, rotation and prices survive untouched.
- **A suspension is a halt, not a number.** Suspended rows get one synthetic `"… was listed as suspended in the official PSE Daily Quotation Report"` (`Disclosure`, source `PSE DQR`) disclosure, deduped per session, which `PseDisclosureClassifier` maps to `TRADING_HALT_RISK` (a hard disqualifier). They count toward `UpdatedMetricCount` but not `MatchedTickerCount`.
- **The macro dials are read-only context.** `Us10YClosePct` / `Us10YChange20dBps`, `BrentUsd` / `BrentChange20dPct`, `EpheCloseUsd` / `EpheChange20dPct` are fetched concurrently after the tape, stored on the snapshot and printed into the prompt's `CROSS-ASSET:` line; they never gate a verdict or a size, and any missing series prints `n/a`.
- **Provenance beats inference.** `ForeignFlowSource` is persisted and surfaced in the prompt and the regime tile, so a reviewer can tell a live DQR from an operator upload from an unreported session.

### Defensive parsing
`SignalJsonParser`:
- Extracts the **outermost balanced JSON object**, ignoring braces inside strings (handles markdown fences and prose).
- `PropertyNameCaseInsensitive`, numeric strings allowed, comments skipped, trailing commas allowed.
- Validates the trading contract: 1–10 unique picks, ranks 1–10, entry > 0, stop < entry, target > entry, conviction 0–100, non-empty thesis, valid drop category and reason.
- Returns `SignalParseResult` with human-readable errors used in the retry prompt.

### Pure, testable domain math
- `QuantitativeFilterService` is stateless and deterministic; all indicator helpers are `public static` for direct unit testing.
- Pre-score weights (0–100): trend alignment 30, RSI band 20, volume expansion 15, foreign-flow tilt 15, structure proximity 20.
- When foreign flow is `null` (the live tape reports none until a DQR is parsed) the verified 85-point technical total is rescaled to 0–100 (`TechnicalScoreMaximum = 85`), so no phantom points are awarded; when a DQR supplies the flow the 15 foreign points apply and the score is **not** rescaled.
- Every indicator (`rsi`, `ema20`, `sma50`, `sma200`, `atr`) is required; a stock missing any of them is skipped instead of being scored on a default. `sma150`, `week52High`, `weinsteinStage`, session `open/high/low`, `atrPct`, `volatilityContractionRatio`, `relativeStrength63d` and the shrunk `empiricalWinRate` are computed alongside and may be `null` on short histories.
- Quant factors that feed the probability: `ComputeRelativeStrength63d` (stock 63-session return minus the PSEi's, in percentage points, `null` without an index series), `ComputeVolatilityContractionRatio` (last 6-bar range ÷ prior 30-bar range, VCP), `ComputeAtrPct`, `ComputeMarketBreadth`, `ComputeUpDownVolumeRatio` (advancing ÷ declining volume, 20D), `ComputeChaikinMoneyFlow` (−1…1 close-location flow), `ComputeTrendEfficiency` (Kaufman ER, 63D), `ComputeBeta` (vs the PSEi, 252D, date-matched), `ComputeMaxDrawdownPct` (252D) and `ComputeRealizedVolatilityPct`. `ComputeHorizonScore` adds +4 for RS63d > 0 and +4 for a VCP ratio below ~0.85.
- **Per-horizon hit rates are stored together.** `ProbabilisticEdgeService.ComputeHorizonBaseRates(bars)` returns a `SignalHorizon → decimal?` map in one pass, persisted as `EmpiricalWinRateDay` / `EmpiricalWinRateMonth` / `EmpiricalWinRateYear`; the singular `EmpiricalWinRate` column stays as the default for rows written before the per-horizon pass.
- `PseBoardLotService` centralizes the **official 15-tier** PSE board-lot/tick table (₱0.0001→₱5,000+, finest tick ₱0.0001), midpoint-away-from-zero rounding, bracket-crossing re-rounding, `GetBoardLotSize`, `RoundSharesToBoardLot(budget, price)`, R:R (gross and fee-adjusted with `BuyLegFeeRate = 0.295%` / `SellLegFeeRate = 0.395%`, round trip `0.690%`), the `target > entry > stop` repair invariant, and the static band (`FloorToTick(close*1.5)` / `CeilingToTick(close*0.7)` with `ValidateAgainstStaticThresholds`). It also owns the expectancy layer: `ComputeNetRewardPerShare`, `ComputeNetRiskPerShare`, `ComputeBreakEvenWinRate`, `ComputeExpectedValueR`, `ComputeQuarterKellyFraction`, `SizePositionByRiskBudget` → `RiskSizedPosition`.
- **Indicators are computed once per series, never once per prefix.** `ComputeEmaSeries(closes, period)` is the single O(n) EMA (seeded from the `period`-bar SMA, `null` before the seed) that `ComputeEma`, `BacktestService.BuildCausalEma20` and the replay's `BuildEma20Series` (one series per ticker instead of one per bar) all call. `IsAscendingByDate` lets `EvaluateStock` skip its defensive sort; the Weinstein prior average, the short ATR, the Kaufman efficiency window and the 20-session mean/median/active-day/turnover statistics are summed by index and filled in **one pass** over the trailing window (`ComputeMedianTurnover` sorts a reused `decimal[]`), and `BacktestService` memoises the index regime per date (`regimeByDate`) instead of re-reading the PSEi series per bar. All of it is gated on the golden snapshots below, so the published numbers are unchanged byte-for-byte.
- `PseDisclosureClassifier` maps PSE Edge headlines onto `DisclosureCategory` (17-Q/17-A/17-C/23-B, dividend, SRO, FOO, tender offer, buyback, trading halt, index rebalance, general) and derives `PseTrapFlag`s; hard traps (`SRO_DILUTION`, `TENDER_OFFER_PIN`, `TRADING_HALT_RISK`) disqualify a candidate, the rest are warnings.
- `HorizonProfile` holds every per-horizon parameter (mission text, `MinHistoryBars`, RSI band, ATR stop/target multiples, disclosure lookback, hysteresis delta, net-R:R requirement, preferred knowledge categories) so `DAY`/`WEEK`/`MONTH`/`YEAR` behaviour is auditable in one file.

- DI: `AddHttpClient<OllamaEmbeddingClient>`, `AddHttpClient<PseMarketDataProvider>` (with the pooled `SocketsHttpHandler`), `AddSingleton<MarketDataCache>`, `IKnowledgeRepository` → `KnowledgeRepository`, `IKnowledgeRetrievalService` → `SqliteKnowledgeService`, hosted `KnowledgeBaseInitializer` before `DailySignalSchedulerService`.
- API maps domain exceptions:
  - `OllamaConfigurationException` → 400
  - `MarketDataUnavailableException` → 503
  - `SignalGenerationException` → 502
  - Delete of a `builtin` knowledge document → **409**; empty/oversized upload → 400; unknown document id → 404
  - Invalid date/ticker → 400; unknown session/ticker history → 404
  - Quotation-report upload: missing file / oversized / unsupported extension / unreadable report → 400; no stored session for the report's date → 404
  - Client-aborted request (`RequestAborted` signaled) → **499** with no body
- `AddProblemDetails()` + `UseExceptionHandler()` produce RFC 7807 responses.
- `RequestCancellationMiddleware` is registered **inside** `UseExceptionHandler()` (i.e. after it
  in the pipeline) so aborted requests are caught before the problem-details handler and never
  logged as server faults. It swallows `OperationCanceledException`/`TaskCanceledException` only
  when `HttpContext.RequestAborted.IsCancellationRequested`, logs at Debug and sets 499 when the
  response has not started. Browsers abort constantly (React StrictMode remounts cancel the
  first fetch, date/horizon switches and dialog closes cancel in-flight loads), which is what
  EF Core reports as `TaskCanceledException` from `RelationalConnection.OpenInternalAsync`.
- Caller cancellation is never a feed failure: `PseMarketDataProvider` rethrows it (guarded by
  `when (cancellationToken.IsCancellationRequested)`) and only its own linked
  `MarketData:RequestTimeoutSeconds` timeout becomes `MarketDataUnavailableException` (503).
  `OllamaSignalEngine` follows the same split.

### The wave layer (market call, four-step plans, own-it check)

- **One server call, never a browser opinion.** `MarketDirectionService.Evaluate(snapshot, run)` sums five deterministic pillar tilts onto a neutral 50 and clamps to **10–90**: index trend ≤ 20, breadth ≤ 14, sector rotation ≤ 8, reported net foreign flow ≤ 6, volatility/peso backdrop ≤ 6. `Call` is `RIDE_THE_WAVE` at ≥ 60, `BE_SELECTIVE` at ≥ 45, else `STAY_IN_CASH`; a stored `BEARISH` regime forces cash; a green call with zero actionable picks steps down to selective; `Direction` reads ≥ 60 / ≤ 40 as `UPTREND` / `DOWNTREND`. A dial that was not reported is **omitted from the sum** and named in `Reasons` — it is never scored as zero. `Confidence` depends on how many pillars reported and how much they agreed. Same session in, same traffic light out.
- **The four-step roadmap is priced on the tick grid.** `WaveTradePlanCalculator` turns the normalized plan into `WaveTradePlanDto`: `IdealBuyPrice`, `CutLossPrice`, fee-paid `BreakEvenStopPrice`, `TargetPrice`, `MaxChasePrice` (a cap of ideal entry + 20% of the reward — the `DAY` static ceiling if lower — walked down tick by tick until the *net* R:R still clears `MinNetRiskReward = 1.25`, or `DayMinNetRiskReward = 2.0` on `DAY`, and never below the ideal entry), `LockBreakEvenTriggerPrice` (+1R), `TrailWaveTriggerPrice` (+1.5R) with an optional `TrailStopPrice`, `EntryStatus` (`READY_NOW` / `NEAR_ENTRY` / `EXTENDED_WAIT_PULLBACK` / `BROKEN_BELOW_STOP` / `WAIT_WATCH_ONLY`) and `MaxHoldTradingDays`. Optional legs are `null`, never `0`.
- **Positions are graded from the owner's own numbers.** `WaveTradePlanCalculator.EvaluateHolding` prices everything from `averageCost` (and, when given, `shares`) after the round-trip fee, then walks one ladder: `STOP_BREACHED` → `TARGET_REACHED` → `TRAIL_STOP_EMA20` → `MOVE_STOP_TO_BREAKEVEN` → `HOLD`, each with a headline, an explanation, a fee-paid `NetReturnPct` / `UnrealizedNetPnlPhp` / `UnrealizedR` and a `RecommendedTrimShares` that is a whole board lot on both legs and never more than half the position. The ladder order is the policy: cutting a broken thesis outranks booking a winner.
- **Transport stays additive.** `MarketDirectionForecastDto` and `TrustPulseDto` hang off the run envelope (`SignalsController.BuildEnvelopeAsync` calls `MarketDirectionService.ToTrustPulse(scorecard)`); each `SignalItemDto` gained an optional `WavePlan`; `TickerResearchDto` gained optional `WavePlan` and `PositionAdvice`, and `GET /api/research/{symbol}` accepts `averageCost` + `shares` (400 on an `averageCost` ≤ 0 or a negative `shares`; a share count is optional). Every new field is optional, so an older stored payload or a cached response still deserializes and the UI degrades: no `directionForecast` → `describeMarketMood`, no `wavePlan` → legacy `PlanSteps`.
- **The UI only renders, and only leads with three.** `MarketDirectionHero` draws the traffic light, the score marker and the reasons; `RidingNowStrip` filters on the server's `EntryStatus == READY_NOW` and renders nothing otherwise; `AdviceCardList` slices `buyable.slice(0, 3)` until the reader asks for more and renders `WavePlanGrid` from the plan. No component derives a score, a chase price, a trigger, an action or a trim size.
- **The cache keeps a position read separate.** `queryKeys.researchItem(horizon, query, holding)` appends the holding so "what should I do with my 1,200 shares at ₱12.40" can never be served the plain buy plan; `invalidateQueries('research:item')` still reaches both. Dropping the holding (flipping back to the buy tab, or `Clear my numbers`) restores the plain key, so the plan returns from cache instead of refetching.

### Consumer-fintech layer (theme, names, presets)

- **Theme is one attribute, not a prop.** `lib/theme.ts` (`ThemeMode`, `useTheme`, `applyTheme`, `readStoredTheme`, storage key `psedesk.theme`) sets `data-theme` on `<html>`; the palettes are CSS custom properties in `index.css` (`:root[data-theme='light']` overrides the dark defaults, plus a light `.panel` shadow and `dialog-overlay`). `index.html` carries an inline pre-paint script so the stored theme applies before React mounts, and no component takes a theme prop, so both palettes paint exactly the same payload. The default is the system `prefers-color-scheme` (light when unknown) — a first-time reader is not dropped straight into a dark trading terminal.
- **Simple typography hangs off hooks.** `Button`, `Tabs`, `TechnicalDisclosure`, `Tooltip` and `Dialog` expose `.ui-button` / `.ui-tab` / `.ui-drawer-title` / `.ui-tooltip` / `dialog-overlay` classes, and `data-view-mode` on `<html>` (from `lib/viewMode.ts`) scopes `.simple-copy` / `.simple-label` / `.simple-note` rules. Pro rendering is unaffected because every rule is additive.
- **Simple mode carries a type floor, and it is a rule not a habit.** `[data-view-mode='simple'] .simple-label` is 12px/1.4 and `.simple-note` is 13px/1.55; both out-specify the `text-[9px]`/`text-[10px]` utilities they replace, so a call site only has to add the class to inherit the floor. Every explanatory second line on a Simple surface (plan-step notes, fee disclaimers, ticket warnings, pre-mortem, watch-list copy) carries `.simple-note`, and every small label carries `.simple-label`. Pro's dense 9–11px scale is untouched because the selector is attribute-scoped.
- **Tone is never the only channel.** Any figure rendered with mint/rose also carries a sign or a glyph: `directionGlyph` / `formatDeltaPercent` / `formatDeltaBasisPoints` prefix toned 20D deltas with `▲`/`▼`, verdicts and drops carry words, and `null` always renders `—`. This is deliberate insurance — several Philippine broker apps use the reverse (red-up) palette, and ~8% of male readers are colour-blind.
- **Announcements are one live region, not a toast library.** `App.tsx` mounts a single `aria-live="polite" aria-atomic` node from the first render and feeds it the friendly error, the run notice and the running state in priority order; `Button` sets `aria-busy` while it works, and the Pro "Refreshing…" line is a `role="status"`. Elapsed seconds stay **out** of the region on purpose — a live region that ticks every second is noise.
- **A long action narrates time, never a fabricated stage.** `run-now` renders an elapsed clock (`formatElapsedSeconds`) plus a `.run-progress` indeterminate bar and the sentence that the previous session stays on screen until the new one lands. There is no step list and no percentage because the client cannot know the server's stage; a strip that invents stages would break the same honesty rule as a fabricated price. The bar is `aria-hidden` and collapses to a static band under `prefers-reduced-motion`.
- **Company names are catalog metadata.** `GET /api/research/catalog` republishes `PseTickerCatalog` as `CatalogStockDto`; `TickerResearchService.ResolveTicker` accepts an exact ticker or an unambiguous company name (prefix match), passes ambiguity through untouched, and never widens a miss into a guess. `lib/pseNicknames.ts` layers familiar names (`Jollibee`, `Meralco`, `PLDT`) and a ranked local search over that list; it cannot invent a ticker.
- **Presets build a payload; the server still decides.** `SAFETY_PRESETS` / `BUDGET_PRESETS_PHP` in `lib/plainAdvice.ts` fill a `PortfolioSettingsUpdate` for the welcome banner and the settings tab; `PUT /api/portfolio/settings` clamps and validates every value, and `safetyPresetForSettings` only detects which card the *stored* numbers match (tolerance 0.01, `null` when customised).
- **Friendly failures keep the evidence.** `describeFriendlyError` maps status 0 / 503 / 404 / 400 / other into a title + action sentence + `retryable`, and stores the raw API text in `technical`, which the terminal renders inside a collapsed “Technical details” block instead of hiding it.
- **Beginners get an explicit exit path, not a shopping list.** `OrderBox` prints a research ticket only — "Ticket: N shares", the target and the cut-loss level — plus the sentence "Placing an order is your decision and your broker's execution"; a name that did not qualify renders "Watch only — no ticket" and an empty run renders "Nothing cleared the test today". `BeginnerGuideDialog` states what the desk will not do, and every recording button says `Practise` / `Record in blotter` because the blotter is paper-only. (The step-by-step broker checklist this layer used to render was deleted in the 2026-11-26 compliance pass.)

### Compliance and non-solicitation guardrails

- **The deployment scope is enforced before any endpoint.** `ComplianceGuardMiddleware` (registered in `Program.cs` ahead of the endpoint mapping) does three things in order: `/health` always passes so process/container probes work; in `Compliance:DeploymentMode = PersonalLocal` (the default, and the fallback for any unrecognised value) a request whose `RemoteIpAddress` is not loopback is answered **403** ProblemDetails — scraped Yahoo/PSE data may not be served over a LAN or a public address; in `LicensedCommercial` every `POST`/`PUT`/`PATCH`/`DELETE` must carry `X-PseDesk-Key` matching `Compliance:OperatorApiKey` (env `PSEDESK_OPERATOR_API_KEY`) compared with `CryptographicOperations.FixedTimeEquals` after trimming, → **401** on a mismatch and **503** when the mode is licensed but no key is set (fail closed). `RemoteIpAddress == null` counts as loopback because that is what the in-memory test host reports.
- **The expensive work is bounded, twice.** `WebApi/Services/DeskWorkGate` is a singleton `SemaphoreSlim(1,1)` with a non-blocking `TryEnter()`: `run-now`, `train` and `train-all` answer **409** ProblemDetails ("The desk is already running a job") when another job holds it and release it in a `finally`, so a second press cannot drop the download cache, re-fetch the session and race the first run's rows. On top of that, `WebApi/Services/DeskRateLimitPolicies.Expensive` — registered in `Program.cs` as a fixed one-hour window (`PermitLimit` = `Compliance:ExpensiveRequestsPerHour`, default 30, `Math.Clamp(…, 1, 1000)`, `QueueLimit = 0`) — is attached with `[EnableRateLimiting]` to `run-now`, `backtest`, `train` and `train-all`, and `OnRejected` writes **429** + `Retry-After` + `application/problem+json`. `app.UseRateLimiter()` sits **after** `ComplianceGuardMiddleware` so a refused caller never burns the operator's budget, and the stored-session reads stay uncapped because they are free. `SignalsControllerRateLimitTests` reflects over the controller so a dropped attribute fails the suite.
- **Every output is model posture, never an instruction.** The prompt's rules 10/13, `MarketDirectionService.BuildCopy`, `WaveTradePlanCalculator.BuildHoldingCopy` and the frontend `plainAdvice` readers all phrase findings in the third person ("the model sizes…", "the plan cleared the fee-adjusted test") and never issue an imperative, a personal recommendation or a guaranteed outcome. Verdicts are published as `Qualifies (Full)` / `Qualifies (Half)` / `Watch Only`.
- **Simulated numbers are labelled simulated.** `BacktestPanel` prints the replay's method (five concurrent positions, 1% risk / 6% heat, two names and 35% equity per sector, fractional Kelly, 0.690% round trip plus board-lot slippage, 60-session refit) and the tile reads "Simulated CAGR · annualised · not a forecast"; `ScorecardDialog` distinguishes the paper record from a client account.
- **Nothing enters the corpus without a rights attestation.** `POST /api/knowledge/upload` requires `confirmRightsAndCloudProcessing=true` (400 otherwise) because indexing and retrieving a document both copy it into prompts sent to the cloud model; `KnowledgeBaseDialog` gates the button on the same checkbox.
- **The notices ship with the code and the app.** `LICENSE`, `DISCLAIMER.md`, `PRIVACY.md` and `THIRD_PARTY_NOTICES.md` sit at the repository root; `lib/legalConsent.ts` holds the reader-facing summary, the `psedesk.legalAcceptedVersion` key and `CURRENT_LEGAL_VERSION` (bump it to re-prompt every browser), and `LegalDisclaimerGate` blocks the terminal behind an un-dismissable dialog until the current version is accepted. `App.tsx` keeps a "Review the notice" action in the footer. The gate carries a "Written for one reader" card mirroring `DISCLAIMER.md` §7, so the instruction-shaped copy cannot ship without the single-user caveat next to it.

### Responsive shell, client cache and code splitting

- **Every screen is one layout that reflows, not a second mobile app.** `DialogContent` is a bottom sheet on phones (flush, `max-h-[92dvh]`, `.pb-safe`, grab handle, `dialog-sheet` keyframes with a `prefers-reduced-motion` opt-out) and the same centred modal from `sm` up; `size` (`md|lg|xl`) only widens the modal variant — and each size gets one extra `3xl:` step (58→64rem, 66→76rem, 78→92rem) so the sheet is not a small card in a 2560px window. The sheet is also a **container-query root** (`@container`) and `overscroll-contain`ed, which is why the tile grids, plan steps and tables inside it reflow on a landscape phone, a split window and an ultra-wide monitor from one class list. `BeginnerGuideDialog` opts back down to a readable prose measure (`3xl:w-[min(54rem,88vw)]`) because a width bump is wrong for prose.
- **Wide tables keep a phone shape.** `SignalTable`, `AdviceCardList`, `PortfolioDialog` (book + ledger), `BacktestPanel` and `ModelTrainerPanel` render a card list below `md` (`md:hidden`) and the dense table as `hidden md:block`, so nothing is dropped from the payload — only re-laid-out. The first column stays pinned with `.sticky-col` (opaque, hairline after-shadow) while the rest scrolls; `.sticky-col-2` parks a second cell past the 3rem rank column. Every horizontal scroller uses `.scroll-x` (momentum, `overscroll-behavior-x: contain`, 6px bar) rather than raw `overflow-x-auto`; rails that carry `.no-scrollbar` keep their bar hidden because the utility is scoped `.scroll-x:not(.no-scrollbar)`.
- **`DialogStickyHeader` is the shared title row.** It is `sticky -top-3 sm:-top-6` with the content's own `-mx`/`px` so the close button and the ticker/tab identity never scroll away on a short viewport. Dialogs that used a plain `<header>` were migrated to it.
- **`lib/queryCache.ts` is the only read cache.** A React-free SWR store keyed by `queryKeys` (`signals:latest:*`, `signals:date:*`, `signals:history:*`, `signals:scorecard:*`, `signals:models`, `signals:memory:*`, `signals:backtest:*`, `research:catalog`, `research:item:*`, `portfolio:summary`, `knowledge:list`) with per-family `queryStaleTime`. It stores **verbatim server payloads** — it decides *when* to ask again, never *what* the number is. `fetchQuery` dedupes concurrent callers onto one upstream request with a **ref-counted `AbortController`**: the browser detaching (StrictMode remount, dialog close, horizon switch) never sends a 499 while another caller is still attached. `getSnapshot`/`isQueryFresh` paint first, `setQueryData` seeds a mutation result, `invalidateQueries(prefix)` keeps data on screen while marking it stale, `prefetchQuery` swallows failures, and `clearQueryCache` exists for tests only.
- **Reads paint from memory, then revalidate.** Every reader follows the same effect shape: snapshot → `setState` (or a skeleton when empty) → one-macrotask deferred `fetchQuery` whose cleanup clears the timer and aborts its own caller signal. A failed revalidation keeps the cached payload on screen behind an amber "showing the last …" line instead of blanking the panel.
- **Live-feed endpoints are still action-only.** `run-now`, `backtest` (once its tab is opened) and `research/{query}` are never warmed by a hover; `lib/preloaders.ts` only warms chunks plus the cheap reads (`portfolio:summary`, `signals:scorecard:*`, `models`/`memory`, `research:catalog`, `signals:history:*`, `knowledge:list`). Every preloader is idempotent (one `import()` promise per chunk, one request per key).
- **Dialogs and the Pro table are `lazy()` chunks.** `App` wraps each in `Suspense`, and `TerminalHeader`/`SignalTable`/`AdviceCardList` call the matching preloader on pointer-enter or focus, so intent usually lands on a warm chunk. `vite.config.ts` pins `vendor-react` and `vendor-radix` with a `manualChunks` **function** (Vite 8 bundles with rolldown, which rejects the Rollup object form) so async chunks never duplicate the framework.
- **Viewport and touch foundations live in `index.css`.** `100dvh` shell, `viewport-fit=cover` + `.pb-safe`, 16px inputs on phones (no iOS zoom), `touch-action: manipulation` and no tap highlight, `.no-scrollbar` chip rails, and a pre-paint `theme-color` sync in `index.html`/`lib/theme.ts` so the browser chrome matches the palette before React mounts.
- **One gutter ladder, one type ladder, three extra breakpoints.** `@theme` adds `xs` (30rem = 480px), `3xl` (120rem = 1920px) and `4xl` (160rem = 2560px) on top of Tailwind's shelf. `.shell` is the *only* page gutter — `padding-inline: clamp(0.75rem, 0.45rem + 1.4vw, 3rem)` — so the shell no longer carries a `px-3 sm:px-5 2xl:px-8` ladder that disagrees with itself at each stop; the shell also caps at `112rem`, widens to `128rem` at `3xl`, and `body` pads by `env(safe-area-inset-left/right)` for a notched landscape phone. `.text-fluid-hero` (17→24px, the market-call headline) and `.text-fluid-metric` (16→22px, the Simple summary figures) are `clamp()`-based for the same reason: 18px is too loud at 320px and 20px is too small at 2560px. The tape (`IndicatorTiles`) goes 2 → 3 (`xs`) → 5 (`xl`) → **9 across** (`3xl`, one row per institutional dial), and the Pro book turns into a two-column layout at `3xl` (`minmax(0,1fr) 22rem`, the dropped-names panel as a sidebar) widening to `26rem` at `4xl`.
- **Touch targets are opt-in, not global.** `.tap` raises an element to a 44px floor **only** under `@media (pointer: coarse)`, so the desktop's deliberate 36–40px geometry survives. It is on `Button`'s base classes, the technical-drawer toggle, the signal card's `Details`/`Take` buttons, the table's info and Take cells, the portfolio refresh and the `Show N more` toggle — and deliberately *not* on the segmented controls, the tab rail or the table rows, which are sized together and would break their own alignment.

### Testing patterns

- xUnit `[Fact]`/`[Theory]` with `Assert.*`.
- Pipeline tests use hand-written `FakeSignalRepository`, `FakeMarketDataProvider`, `FakeSignalEngine` and `FakeKnowledgeService` (no mocking library); the knowledge fake records `RetrieveCalls`/`LastQuery` so retrieval wiring is asserted, not implied.
- Tests assert deterministic behavior: exact scores, tick grid membership, board-lot brackets (28 boundary/theory cases), static-band clamping, net-R:R acceptance, drift recomputation, drop classification, unknown-ticker/thesis-less/hard-trap discard, failure when no valid pick remains, and market-data-missing errors.
- New deterministic-money coverage: `PseBoardLotServiceTests` (net reward/risk, break-even rate, EV, Quarter-Kelly, risk-budget sizing, R:R identity), `ProbabilisticEdgeServiceTests` (base-rate shrinkage, barrier geometry blend, bounded tilts, verdict gates, cash posture), `SignalOutcomeServiceTests` (barrier walk, conservative same-bar tie, expiry, realized net R, scorecard aggregation, live calibration offset, the live-drift verdict and its persistence, desk memory) and `QuantitativeFilterServiceTests` (RS63d, VCP, breadth, +RS/VCP horizon score).
- **Closed-loop coverage** uses deterministic stub tapes: `MoneyManagerTrainingServiceTests` asserts the 503-on-empty-feed contract, the four stored `PRIOR_FALLBACK` rows (all twelve factor keys, horizon embargo) and single-horizon refits through a recording `ISignalRepository`; `LearnedEdgeModelTests` pins the promotion gate, the ±6pp saturation, mean imputation and Kelly rebasing; `DailySignalSchedulerRetrainTests` pins the weekly refit calendar and **`NeedsBootstrap`** (true while a horizon is `UNTRAINED`, false once every horizon carries a fitted row, so a `PRIOR_FALLBACK` is never re-fetched on every restart).
- Knowledge tests cover front-matter parsing, chunk splitting, hash stability, mandatory-guardrail injection, horizon and trap boosts, built-in delete protection, Markdown upload scoping, empty-upload rejection and re-index idempotence (`FakeHostEnvironment` supplies the root path).
- Infra/WebApi tests stay offline via `NullLogger<T>.Instance` plus a stubbed `HttpMessageHandler`; `PseMarketDataProviderTests` feeds deterministic chart JSON + a PSE Edge HTML page through the stub so chart parsing, tick rounding and every 503 path are covered without a socket.
- **Golden snapshots guard the output contract.** `SyntheticMarketFixture` builds a seeded, clock- and network-free market batch; `GoldenSnapshot.AssertMatches(name, json)` compares a serialised DTO with `Application/Golden/*.json` (and `PSEDESK_UPDATE_GOLDEN=1` rewrites them). `BacktestGoldenTests` pins all four horizons — equity curve, every trade, fees, slippage, alpha, CAGR, Sharpe — and `QuantitativeFilterGoldenTests` pins `EvaluateStock`'s metrics. ## Conventions

- File-scoped namespaces; `sealed` service classes; records for DTOs/immutable models.
- Async methods take `CancellationToken cancellationToken = default` and flow it through EF/HTTP calls.
- XML doc comments explain **why** a guardrail exists, not just what the method does.
- C# naming: `PascalCase` public members, `_camelCase` private readonly fields; constants in `PascalCase`.
- TypeScript: strict mode, `type`-only imports, named exports, 2-space indent, single quotes, trailing commas.
- **Nothing the model says is trusted for invariants or provenance**: prices, sizing, band limits, drift, drops and citations are all recomputed or verified server-side. **Odds are in the same category** — the win probability, break-even rate, expected value, Kelly fraction and actionability verdict are computed by `ProbabilisticEdgeService` from stored bars and the plan geometry, so a new feature must extend that rule, not bypass it. **The ticket's governor multipliers, sector caps, slippage and execution guidance are equally server-owned**: the browser renders them, never re-derives them.
- **New dependencies need a documented decision** in this file plus a line in `techContext.md` (PdfPig is the only non-framework addition: offline PDF text extraction for uploads; the responsive + caching layer added **none** — it is hand-rolled in `lib/` and `ui/`; the brand icon set added **none** either — see the desk-mark rule below).
- **One drawing, many surfaces (the desk mark).** `lib/deskMarkGeometry.ts` is the single description of the brand mark — three ascending candlesticks on a 32-unit grid, mint on a rounded tile — with no imports at all, so the React build, the `node:test` suite and `scripts/generate-icons.mjs` all load the same numbers. `components/DeskLogo.tsx` renders it in `currentColor` over the tinted badge, so it follows `[data-theme]` like every other figure, while the generator bakes the fixed dark tile into `public/favicon.svg`, `favicon.ico` (16/32/48) and `apple-touch-icon.png` (180px full-bleed). Nothing else may draw the mark, and the hand-written ICO + `node:zlib` PNG writer is the dependency-free answer to "we need three binaries" — do not swap in an icon package without recording the decision here.
- **Emphasis is group `opacity`, never `fill-opacity`.** Each candle's wick and body overlap; per-fill alpha would composite twice and print a darker band through the body. The generator, the SVG and the JSX all put `opacity` on the per-candle group for that reason, and the same trap applies to any future multi-shape mark.
- **Readers go through `lib/queryCache.ts`, never `fetch` from a component.** A new read means a `queryKeys` entry + a `queryStaleTime` family + `fetchQuery`/`prefetchQuery` usage; a mutation means `setQueryData`/`invalidateQueries`. Do not add a second cache, and never cache a computed value — only the server payload.
- **Additive UI props only.** Dialog/Button/Tabs changes must default to the previous behaviour (`size` defaults `md`, `DialogStickyHeader` is optional) so existing callers compile untouched; mobile behaviour belongs in media queries and card fallbacks, not in a second component tree.
- **Responsive rules: fluid first, container second, breakpoint last.** Reach for a `clamp()` utility (`.shell`, `.text-fluid-*`) before a breakpoint ladder, and for a container query (`@container` + `@md:`/`@4xl:`) before a viewport one — a card or a sheet must lay out from the space it actually has, which a viewport breakpoint cannot see. Use viewport variants only for genuinely page-level decisions (the header's `lg` split, the `md:hidden`/`hidden md:block` card-and-table pairs). Any new horizontally scrollable surface uses `.scroll-x` (never bare `overflow-x-auto`) and any compact row action that must be tappable adds `.tap`; the 44px floor is never applied globally because it would break the segmented controls and the dense table. Verified in the built stylesheet, not just in the source: `grep -o "@media (width>=…)"` and `container-type` are the two checks that prove the utilities emitted at all.
- **Fonts are vendored, never linked from a CDN.** The UI typeface is **Google Sans Flex** (variable 100–900), declared as one `@font-face` in `index.css` from `public/fonts/google-sans-flex-latin.woff2` (OFL 1.1, licence shipped beside it), preloaded in `index.html` and named first in `--font-sans`. A `fonts.googleapis.com` `<link>` is forbidden: it would tell a third party who is reading the desk, contradicting `PRIVACY.md` §5 and the "loads with nothing but the API on loopback" guarantee. Only the `latin` subset ships — the API's `latin-ext`/`symbols` subsets were measured (2026-11-26) and do not carry `₱` (U+20B1), `▲`/`▼` (U+25B2/U+25BC) or `→`, which therefore come from the system font exactly as they do behind the official `<link>`; adding them cost ~51 kB for no glyph. Refresh the binary only through `npm run fonts` (`scripts/fetch-fonts.mjs`), which re-reads the Google Fonts CSS and refuses anything that is not a WOFF2.
